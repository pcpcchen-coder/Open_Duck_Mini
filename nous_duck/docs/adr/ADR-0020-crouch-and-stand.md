# ADR-0020：原地蹲低（第一版「坐下」）與起立——開迴路關鍵影格，收手停在原地

- 狀態：**草案（Proposed）**
- 日期：2026-11-28
- 相關：[ADR-0015 草案](ADR-0015-gesture-library.md)（§2.1 把「B 類：開迴路關鍵影格」排除在動作庫外，要另寫 ADR，就是這份）、[ADR-0014](ADR-0014-duckd-head-direct-and-single-process.md)（duckd 直接控制頭部、單一程式占匯流排）、[ADR-0009](ADR-0009-duck-link-transport-and-command-bridge.md)（duck-link、步態 host）、[ADR-0008](ADR-0008-single-board-pi4.md)（單板 Pi 4）
- 依據：[模擬驗證紀錄 2026-11-28](../validation/posture-crouch-sim-2026-11-28.md)（**只有模擬**，腿還沒有在實機上動過）
- 協定：[提案 a-posture-command](../../protocol/proposals/a-posture-command.md)（schema 沒有動）

## 1. 背景

使用者 2026-11-28 要鴨子「原地坐下與起立」。模擬比較了三種坐法（紀錄 §3）：

- 機身水平往下蹲：上游 URDF 的膝蓋限位（90°）內只低 1.1 cm。
- 往後坐到尾巴：一定要「倒」過去，會往後滑十幾公分。
- 使用者在控制台存的「坐下3」（機身貼地）：坐得下去，但重心在腳跟後 6.6 cm，模擬裡站不起來。

使用者選了**蹲低**：腳不動、身體下降約 3.4 cm、機身前傾約 28°、頭抬 0.5 rad，全程重心在鞋底內。

這是 ADR-0015 的 **B 類**動作：不經過步態策略，直接控制腿部關節，沒有平衡回饋。目前實機上**沒有跑步態策略**（`gait_host.py` 只做到載入測試），站姿是舵機控制台或 duckd 用位置控制維持的上游 `init_pos`。

## 2. 決定

### 2.1 放在哪

- 放在 **duckd** 裡，做成一個新的「姿勢」功能：兩個姿勢 `stand`（＝上游 `init_pos`）與 `crouch`（`sim/posture_sim/poses.py` 的 `CROUCH`），以及兩者之間的平滑內插（smoothstep，預設 3 秒）。
- 姿勢的數字只有一份：由 `sim/posture_sim/poses.py` 產生 duckd 讀的 JSON（`robot/duckd/duckd/postures/postures.json`；不放 `library/`，那是動作庫），`sim/tests/test_posture_sim.py` 檢查兩邊一致。
- **實作狀態（2026-11-28）**：`duckd/posture.py` 與 `--legs` 旗標已實作，只能從本機 `duckd-ctl` 下指令；驗證層級是單元測試＋MuJoCo（[紀錄](../validation/duckd-posture-2026-11-28.md)），**沒有實機**。部署的 systemd 服務沒有加 `--legs`。
- **腿要另外接手**：duckd 預設用 `HeadOnlyBus` 擋住腿部 ID。`--legs` 啟動時白名單才加上腿；`engage` 仍然只接手頭部，要另外下 `duckd-ctl engage-legs` 才會接受姿勢動作。釋放時腿的扭力不關（站著時關掉會倒）。**不經 duck-link 接手腿**：Nous 只能要求「蹲下／站起」，不能讓腿出力。
- **和步態策略互斥**：之後步態 host 接上實機時，姿勢動作只能在「策略暫停」時執行，執行完回到站姿才交還。交接的規則等步態 host 上實機時另寫，本 ADR 不處理。
- **和舵機控制台互斥**：照 ADR-0014，同一時間只有一個程式占匯流排；控制台連著時 engage 會被拒絕。

### 2.2 收手（安全）

模擬的關鍵發現：**從任何姿勢放鬆（降 kp）都會往前倒**；**停在目前目標**則在蹲到 25／50／75／100% 時都站得住，之後也能站回來。所以：

| 情況 | 做法 |
|---|---|
| `stop`、duck-link 斷線、租約過期、逾時 | **停在目前目標**，原地保持；之後只接受「慢慢回站姿」 |
| 低電壓（舵機電壓 < 控制台的 6.6 V 警告值） | 不開始新的姿勢動作；動作中就停在原地，再用 6 秒慢慢回站姿 |
| 過熱（任一顆 ≥ 55°C 警告、≥ 65°C 停止） | 警告：不開始新動作，動作中就停在原地；停止：發緊急停止，`--legs` 時 14 顆都**放鬆**（舵機控制台 Controller 的規則）。過熱時繼續出力會燒舵機，倒下的風險比較小 |
| 本機緊急停止（`duckd-ctl estop`、`SIGUSR1`） | `--legs` 時 14 顆都放鬆。要「停在原地」請用 `duckd-ctl posture-stop` |
| 腿的跟隨誤差 > 20° 持續 0.5 秒 | 停在原地並記錄 `tracking_error`（腿被擋住、被抱起來或倒了）。沒有 IMU 時這是唯一的自動判斷 |
| 過流或舵機回報過載旗標 | 同過熱停止 |
| 跌倒（IMU 俯仰或側傾 > 45°，或機身高度推算異常） | **放鬆**並發緊急停止：已經倒了，繼續出力只會傷舵機 |
| 控制迴圈晚了（overrun） | **時間軸跟著暫停**，恢復後從原處接著走，不讓目標直接跳到牆上時間該到的位置（模擬：卡 1 秒後直接跳，力矩打到上限 3.23 N·m；暫停則 0.67 N·m） |

- 跌倒判斷要用 IMU。BNO055 在 Pi 硬體 I2C 上讀值會錯第 7 位元；2026-11-28 改用 i2c-gpio 後 60000 次讀取 0 錯（[紀錄](../validation/bno055-i2c-2026-11-28.md)）。duckd 還沒讀 IMU、IMU 也還沒校正，所以**目前跌倒判斷只能靠人在旁邊看**，duckd 不能宣稱有跌倒保護。
- 每次實機讓腿出力都要使用者當下同意、人在旁邊、鴨子先架高或扶著（整合線規則）。

### 2.3 頭與眼睛

- 頭：模擬算出蹲低時 `head_pitch` 要 +0.506 rad 臉才朝前，但 duckd 的頭部範圍上限是 0.3 rad（ADR-0009 §2.5）。**第一版頭不跟著補償**（蹲低時臉朝下約 28°），頭照舊由仲裁器控制（`look`、`track`、動作都照常）。要不要放寬 head_pitch 上限另外決定；模擬裡「頭不抬」也一樣穩（紀錄 §4）。
- 眼睛：動作中顯示「專心」類表情（用現有 `express` 的名稱，不新增）；蹲好後回到平常的表情。
- 天線、音效：不在這一版。

### 2.4 速度

預設 3 秒蹲、3 秒起；duck-link 的 `duration_s` 可以要求 3～10 秒，**不能比 3 秒快**（模擬 1.5 秒也過，但實機還沒驗證）。

## 3. 實機驗證步驟（下一個批次以後）

1. I2C 降速、確認 BNO055 讀值穩定（要使用者同意重開 Pi）。
2. 足底開關按壓測試（使用者按、duckd 只讀）。
3. **架高**（腳不著地）跑一次蹲下、起立，只看關節角度跟目標的差、溫度、電壓。
4. **著地、人扶著**跑一次，速度 6 秒。
5. 著地、人在旁邊不扶，跑 3 秒版本。

每一步都寫驗證紀錄；任何一步失敗就停在那一步。

## 4. 後果

- 好處：不用訓練、數字可以在模擬裡檢查，收手規則清楚。
- 代價：沒有平衡回饋，地面不平或被推就沒有保護；看起來比較像「趴低」，不像真的坐在地上。真的坐下（「坐下3」那種）要能站起來，需要動態動作或訓練新策略（ADR-0015 的 C 類），另開批次。
- duck-link 要新增指令與狀態（提案 a-posture-command），在 schema 升版之前 duckd 只開放本機指令（`duckd-ctl posture crouch|stand`）。
