# ADR-0002：室內定位與導航

- 狀態：**草案（Proposed）**；2026-11-12 使用者同意在家裡貼 AprilTag（§8 第 1 項已決定）；2026-11-13 使用者同意沒開燈時以**紅外線補光燈為主**（§4.1）
- 日期：2026-11-12
- 相關：[R-001](../requirements/R-001-mobile-companion.md)、[ADR-0005](ADR-0005-compute-and-sensor-upgrade.md)（運算與感測器）、[ADR-0004](ADR-0004-docking-and-charging.md)（回充）

## 1. 背景與限制

使用者要鴨子像掃地機器人一樣導航，能「去某個房間做某件事」。限制：

1. **不能用步數推估位置**。雙足步態會打滑，腳步長度隨地面、速度、電壓改變，誤差會一直累積。上游 runtime 送出的只是速度指令（前後、左右、轉向），不保證實際走了多少。
2. 掃地機器人靠的是**輪子里程計＋光達（LiDAR）**。鴨子沒有輪子；光達要求感測器大致保持水平，雙足走路時身體會晃動與前後傾，再加上重量與外觀，**不適合當主方案**（§6 有比較）。
3. 鴨子很慢：上游手把映射的最高前進速度是 0.15 m/s，橫跨一個家要一到數分鐘。
4. 鴨子不能開門、不能爬樓梯、跌倒後不能自己站起來。
5. 定位與局部導航要在**鴨子本機**完成，Wi-Fi 斷線時才能安全停住（ADR-0001 的原則）。

## 2. 核心想法：「絕對定位為主、相對追蹤補空檔」

既然相對推估（步數）一定會漂移，就讓位置**經常被絕對參考點校正**。分三層：

| 層 | 作用 | 方法 | 精度目標（草案，未量測） |
|---|---|---|---|
| L1 相對追蹤 | 兩次校正之間，知道自己大概移動了多少、轉了多少 | **視覺慣性里程計（VIO）**：雙目影像特徵追蹤＋BNO055 IMU 融合；IMU 的陀螺儀提供轉向。**不用步數** | 每走 1 m 漂移數公分到十幾公分 |
| L2 絕對校正 | 把漂移歸零，並直接知道「我在哪個房間」 | **AprilTag 標籤**：貼在每個門框兩側、房間內幾個點與充電座上；雙目看到標籤即可算出相對於標籤的 6 自由度位姿 | 看到標籤時，2 m 內約 ±5 cm（待量測） |
| L3 地圖重定位（第二階段） | 不靠標籤也能認出位置，減少要貼的標籤 | 用帶看時錄下的影像在 Mac 建視覺地圖（例如 RTAB-Map），鴨子以影像特徵比對重定位 | 待評估 |

融合：以濾波器（EKF）或位姿圖把 L1、L2、L3 合併，**每個位置估計都帶不確定度**。不確定度超過門檻時，鴨子不繼續盲走（§5.3）。

為什麼選 AprilTag 當第一階段的主力：

- **便宜、可靠、運算量小**：印在紙上就能用，偵測演算法成熟（開源 apriltag 函式庫，BSD 授權），在感知板上能即時跑。
- **標籤 ID 直接等於地點**：看到 `tag 12` 就知道是「哥哥房門內側」，不用猜。
- 不受打滑影響，也不受光線變化太大影響（只要看得見）。
- 缺點是要在家裡貼標籤；L3 做好後可以減少數量。

## 3. 地圖

### 3.1 兩層地圖

1. **拓撲圖（主要）**：節點是房間與地點（`living_room`、`brother_room`、`brother_bedside`、`dock`），邊是門口與走道。任務「去哥哥房間」只需要在拓撲圖上找路徑。
2. **每層樓的平面柵格圖（輔助）**：2D 佔據格（occupancy grid），由帶看時的雙目深度建立，用來規劃房間內的路徑與避開家具；標出禁區。

### 3.2 地圖資料（存在 Nous 本機，不進 repo）

| 資料 | 內容 |
|---|---|
| `places` | 地點 ID、所屬房間、在平面圖上的位置、本機顯示名稱（例如真實的「哥哥房間」）|
| `tags` | 每個 AprilTag 的 ID 與在地圖上的位姿 |
| `edges` | 門口、走道、是否需要門開著 |
| `no_go` | 禁區：**樓梯口（必填）**、厚地毯、門檻過高處、寵物碗、電線區 |
| `grid` | 平面佔據格 |
| `map_version` | 版本號；鴨子與 Nous 用同一版 |

地圖含家中格局與照片特徵，屬隱私資料：只存在 Mac mini 與鴨子本機，**不進版控、不外傳**。

### 3.3 建圖流程：「帶看模式」

1. 在門框兩側、房間中央附近、充電座上貼 AprilTag（tag36h11 家族；尺寸與高度依鏡頭高度與視角決定，P4 實測）。
2. 使用者用手把或讓鴨子跟著走，帶鴨子逛一遍家（走慢一點）。鴨子錄下雙目影像、IMU、標籤觀測。
3. 經過每個地點時，使用者用語音命名：「這裡是哥哥的房間」「這裡是哥哥床邊」。Nous 把名稱存在本機，地圖裡只放 ID。
4. Mac mini 離線處理錄下的資料：算出標籤位姿、拼出平面柵格圖（L3 階段再建視覺地圖）。
5. 使用者在 Mac 上的簡單頁面確認地圖、畫禁區（至少把樓梯口標出來）。
6. 下載到鴨子。

## 4. 定位運作

```text
雙目影像 ─┬─► VIO（特徵追蹤＋IMU）───────────────┐
          ├─► AprilTag 偵測 ─► 已知標籤位姿 ──────┼─► 融合（EKF／位姿圖）─► 位姿＋不確定度＋所在房間
          └─► 深度 ─► 局部障礙圖                  │
頸頭關節角度（舵機回讀，鏡頭在頭上時）─────────────┘
BNO055 IMU ─────────────────────────────────────┘
```

- 鏡頭裝在頭上時（ADR-0005 §2.3），要用 4 個頸頭關節的回讀角度把鏡頭位姿換算到身體，且影像與關節讀值要時間同步。
- 走路時頭會隨步態晃動；VIO 要能承受，或在低速／停下時做較多校正。
- 校正時機：每次看到標籤就校正；長走廊或大房間標籤少時，主動**停下轉頭掃描**找標籤（頭部可以 yaw／pitch，這點比掃地機器人有利）。

### 4.1 沒開燈時的備案：紅外線補光（2026-11-13 使用者同意以此為主）

**問題**：整套定位靠雙目鏡頭被動收光。沒開燈時，AprilTag 讀不到、VIO 追不到特徵、雙目深度也算不出來。深度失效代表**避障與落差偵測也一起失效**，這比定位失效更危險。

**需要摸黑走的情況**（ADR-0006 的夜間模式本來就不主動走動，待使用者確認範圍）：

- 早上叫人起床時，拉著窗簾的臥室可能還很暗（ADR-0006 §5 把排程的叫起床任務列為夜間例外）。
- 回充電座時，客廳或走廊已經關燈。
- 傍晚有人關燈時，任務還在進行中。

**決定**：在頭上 AR0144 鏡頭旁加 **850 nm 紅外線補光燈**，沿用現有的 AprilTag＋VIO＋雙目深度流程，家裡不用另外布線或放有電源的設備。

| 項目 | 作法 | 狀態 |
|---|---|---|
| 補光燈位置 | 頭殼上、緊貼兩顆鏡頭（與鏡頭同軸附近，下面的反光貼紙才有效）；隨頭部轉動，轉頭掃描時一起照 | 跟頭殼重新設計一起做（ADR-0005 §2.3） |
| 波長 | 先用 **850 nm**：一般 CMOS 感光度比 940 nm 好；代價是 LED 本身看得到微弱暗紅光。940 nm 人眼幾乎看不到，但影像較暗 | 待實測比較 |
| 何時開 | 只在**鏡頭已經開著**（導航、找人、回充）而且畫面太暗時才開；亮度依曝光自動調低，夠用就好 | 規則草案 |
| 鏡頭前提 | AR0144 模組**不能有濾紅外線的濾片**（IR-cut），否則補光無效。測法：拿電視遙控器對鏡頭按，畫面上看得到遙控器的燈在閃就可以用 | **待驗證**（尚未測） |
| 標籤印法 | AprilTag 用**雷射印表機**印：碳粉在紅外線下仍是黑的；部分噴墨的染料墨水在紅外線下會變透明，標籤就讀不到。印好後在紅外線下拍一張確認 | 規則草案；張貼前驗證 |
| 反光貼紙（選配） | 在充電座與門框的標籤旁加反光貼紙；紅外線照過去會很亮，遠處先找到方向，靠近再讀標籤 | 選配，視實測距離決定 |
| 讀標籤時停下 | 沿用 §4「停下轉頭掃描」：站著不動時把曝光時間拉長，在光線不足時讀標籤，不會因晃動而模糊 | 規則草案 |
| 雙目深度 | 補光讓暗處有紋理，深度可以繼續用；若仍不夠，再評估加點陣投射器（主動雙目） | 待實測 |

**要實測的數字**（P2 上機後量，結果寫進 `docs/validation/`；目前都**沒有量測**）：補光有效距離（預估約 2～3 m，只是經驗值）、各距離下 AprilTag 的偵測率與位姿誤差、補光燈耗電與發熱、對續航的影響、加在頭上的重量（ADR-0005 §2.4 頸部扭力）。

**不管補光是否成功，都要有的安全規則**：

1. **太暗就不走**：畫面平均亮度、可追蹤特徵點數或深度有效比例低於門檻（門檻待定）時，鴨子停下站好，回報「太暗了，我看不到路」，**不摸黑前進**。在鴨子本機判斷，不依賴 Nous（ADR-0001）；這也是 ADR-0006 §2.1 第 4 條「不能盲走」的具體化。
2. **不靠光線的落差偵測（建議）**：在身上加一顆朝前下方的多區塊 ToF 測距感測器（例如 VL53L5CX 一類，型號待選），偵測樓梯口與落差。這樣禁區保護在暗處也不是只靠視覺單一來源（§5.3「雙重保護」）。

**輔助手段（非必要，可疊加）**：

- 走廊、門口插小夜燈：最便宜，家人起床走路也用得到；臥室不適用。
- 家裡有智慧燈泡的話，由 Nous 開燈；會吵醒人，只適合沒人睡覺的區域。
- 藍牙信標（訊號強度 RSSI）：只到房間層級，**不能拿來導航或穿過門口**；可當「大概在哪個房間」的先驗，縮小找標籤的範圍、迷路時回報大概位置。要不要加待使用者決定（§8）。

**隱私**：有紅外線之後，鏡頭在黑暗的臥室裡也看得到睡著的人。ADR-0006 的固定規則全部適用（原始影像不寫檔、不外傳；鏡頭開啟時眼燈要提示），夜間是否允許在臥室開紅外線另列為可開關設定（ADR-0006 §2.2）。

## 5. 導航

### 5.1 全域規劃

1. 拓撲圖上找房間到房間的路徑（例如 客廳 → 走廊 → 哥哥房門 → 哥哥房間 → 床邊）。
2. 每段在柵格圖上以 A* 規劃路點，避開禁區。

### 5.2 局部控制

- 依目前位姿與下一個路點，算出速度指令（前後 `vx`、左右 `vy`、轉向 `yaw_rate`），送給身體板，經 safety 夾限後交給上游步態策略。**上游 runtime 接受的本來就是這三個速度**，跟一般移動機器人的 `cmd_vel` 相同，導航層不用知道步態細節。
- 雙目深度建局部障礙圖，即時避開人、寵物、臨時物品。
- 速度保守：靠近障礙物、門口、轉彎時降速。

### 5.3 異常處理

| 狀況 | 行為 |
|---|---|
| 不確定度過高（迷路） | 停下 → 轉頭掃描找標籤 → 原地小角度轉身再掃 → 仍找不到就停在原地，回報 Nous「我迷路了，在某某附近」 |
| 門關著（深度看到門板、拓撲邊不通） | 停在門口，回報「房門關著」；由 Nous 決定改在門口說話或放棄 |
| 前方有落差（深度偵測）或接近禁區 | 立即停止、後退；禁區由地圖與即時深度**雙重**保護，樓梯口不依賴單一來源 |
| 路被擋住 | 重新規劃；多次失敗就回報 |
| 跌倒 | 身體板 safety 立即停止；回報「我跌倒了，需要幫忙扶起來」（無法自己站起） |
| 太暗（補光後畫面仍太暗、特徵或深度不足） | 立即停下站好，回報「太暗了，我看不到路」；不摸黑前進（§4.1） |
| Wi-Fi 斷線 | 可以把目前這一段走完到安全點再停，或立即停；**預設立即停下站好**，不繼續任務 |

### 5.4 軟體框架

候選：感知板跑 **ROS 2**，使用成熟元件（apriltag 偵測、RTAB-Map 或其他 VIO／SLAM、Nav2 導航），速度指令經橋接送到身體板。優點是不用自己寫 SLAM 與路徑規劃；缺點是在小型板子上的資源佔用與維護成本。

替代：第一階段自己寫最小 Python 版（AprilTag＋IMU 航向＋拓撲路點），之後再換 ROS 2。

**決定方式**：P4 前先做 spike，在 `sim/` 的 MuJoCo 場景（加入牆、門、AprilTag 貼圖）與感知板實機上比較 CPU、記憶體、延遲，再定案。

## 6. 其他定位方案比較

| 方案 | 優點 | 缺點 | 結論 |
|---|---|---|---|
| 步數推估（腳步里程計） | 不用額外硬體 | 打滑、累積誤差，使用者已排除 | 不採用 |
| **AprilTag＋VIO（本 ADR）** | 便宜、可靠、直接認出房間、不受打滑影響 | 要貼標籤；要看得見 | **第一階段主方案** |
| 視覺地圖重定位（RTAB-Map 等） | 不用標籤 | 運算量大、光線與家具變動會影響 | 第二階段，減少標籤 |
| 2D 光達 SLAM（掃地機器人作法） | 成熟、精準 | 身體晃動與前後傾讓 2D 掃描失準；加重量與改外觀；高度約 30～40 cm 只看得到家具腳 | 不建議當主方案；若視覺不夠再評估 |
| **紅外線補光燈＋AprilTag（§4.1）** | 人眼幾乎看不到；家裡不用布線；現有視覺流程與深度都能繼續用 | 鏡頭不能有 IR-cut 濾片；耗電、頭部變重；照射距離有限（待量測） | **沒開燈時的主備案**（2026-11-13 使用者同意） |
| 白光頭燈 | 最簡單，流程完全不改 | 會照醒睡覺的人，與夜間模式衝突 | 不採用為主備案；沒人睡覺的區域可再評估 |
| 藍牙信標（訊號強度 RSSI） | Pi 4 內建藍牙；信標便宜、用電池 | 一般約 1～3 m 級且會跳（經驗值，未量測）；人體遮擋與反射影響大；分不出門的兩側 | 只可當房間層級輔助（§4.1），是否加待決 |
| 藍牙測向（AoA）、藍牙通道測距（Channel Sounding） | 不怕暗，可到公尺以下 | 要天線陣列或新晶片，硬體生態尚未成熟（待查證） | 暫不評估 |
| UWB 定位（每個房間放錨點） | 不怕光線、不用看得見，10～30 cm 級（依產品） | 每個房間要放有電源的錨點；設備費用 | 備案：若標籤不美觀或視覺不穩再評估 |
| Wi-Fi 訊號強度指紋 | 不用額外硬體 | 只能粗略到房間，不夠導航 | 只可當輔助判斷 |
| 天花板或固定鏡頭追蹤 | 鴨子端最輕 | 每個房間都要裝鏡頭；更大的隱私問題 | 不採用 |

## 7. 後果

- 家裡要貼 AprilTag，需要使用者同意位置與數量（建議先從「客廳、走廊、哥哥房間、充電座」四處開始）。
- 需要新的 `robot/navigation/`、`robot/perception/`（感知板）與 Mac 端的建圖工具。
- duck-link 要新增：位姿與所在地點的 state、任務（mission）訊息、地圖版本（見 [`protocol/`](../../protocol/README.md)）。
- 導航需要長時間任務，Nous 端改成非同步任務模式（[ADR-0001 §7](ADR-0001-duck-role-in-nous.md#7-2026-11-12-修訂行動夥伴)）。
- 沒開燈的備案（§4.1）：頭殼重新設計要預留紅外線補光燈；AprilTag 改用雷射印表機印；感知板要加「太暗就不走」判斷；建議加 ToF 落差感測器（ADR-0005 §2.2）；ADR-0006 新增夜間紅外線的隱私設定。
