# ADR-0003：行動終端、喚醒詞與找人

- 狀態：**草案（Proposed）**
- 日期：2026-11-12
- 相關：[R-001](../requirements/R-001-mobile-companion.md)、[ADR-0001](ADR-0001-duck-role-in-nous.md)、[ADR-0002](ADR-0002-indoor-localization-and-navigation.md)、[ADR-0005](ADR-0005-compute-and-sensor-upgrade.md)
- AIOS 參考（唯讀，main `7b0257d`）：`terminals/rpi4/`、`docs/adr/ADR-0001-local-family-recognition.md`（本機家人辨識）、`docs/adr/ADR-0003-local-wake-and-voice-recognition.md`（本機喚醒與聲音辨識）、`docs/Current_Implementation_Status.md`

## 1. 背景

- AIOS 的 Raspberry Pi 4 終端：Mac mini 跑 Nous 核心；Pi 用自己的螢幕（電子腦）、eMeet 麥克風、雙目鏡頭與喇叭，在**固定區域**跟使用者互動。Pi 的 Chromium 開 `http://localhost:<port>`，經 SSH 轉送連到 Mac 的 loopback。
- AIOS 已有：
  - 喚醒詞「Hello Nous」「Hey Nous」：sherpa-onnx KWS（Apache-2.0、**開放詞彙，換詞不用錄樣本或訓練**），鎖 2.0.x，旗標 `NOUS_WAKE` 預設關閉。
  - 家人音色辨認（聲紋）與本機家人臉部辨識（YuNet＋SFace），登記資料（gallery）只在 Mac 核心，比對在核心做。
- R-001 要求：鴨子帶著麥克風、喇叭與雙目鏡頭，走到任何地方都能對話；有自己的喚醒詞；被叫醒後**走去找是誰叫它**。

## 2. 決定：鴨子是「會走路的 Nous 終端」

修訂 ADR-0001 的 DuckTerminal：鴨子不再只有事件與表情，而是一個完整的行動終端（麥克風、喇叭、鏡頭），角色比照 rpi4 終端，但**沒有螢幕**、**會移動**。

| | rpi4 終端 | 鴨子終端 |
|---|---|---|
| 位置 | 固定 | 會移動；靠充電座時等同固定終端（ADR-0004） |
| 輸出 | 螢幕電子腦＋喇叭 | 喇叭＋頭部動作、天線、眼燈（表情套件） |
| 輸入 | eMeet 麥克風、雙目鏡頭 | 鴨子上的麥克風陣列、雙目鏡頭 |
| 大腦 | Mac 上的 Nous 核心 | 同左 |
| 連線 | SSH 轉送到 Mac loopback | 待決（[architecture §6](../architecture.md#6-傳輸待決)），傾向同樣模式 |

電子腦的「腦區連動」是 AIOS 使用者指定的設計要求；鴨子沒有螢幕，之後可以考慮用眼燈或天線呈現**由真實事件驅動**的狀態，但不假裝是腦部活動。

### 2.1 終端軟體：兩條路線，先做可行性 spike

| 路線 | 作法 | 優點 | 缺點 |
|---|---|---|---|
| A. 沿用 AIOS 頁面 | 感知板跑 Chromium（不需要接螢幕），開同一個 Nous 頁面，就像 rpi4 終端 | 最大程度重用 AIOS 已有的即時語音、喚醒、辨識程式 | Chromium 吃資源；頁面的鏡頭感測是為固定位置設計的，移動中要調整；音訊裝置與 DOA 不經過頁面 |
| B. 原生終端程式 | 感知板跑 Python 程式：sherpa-onnx 喚醒、音訊串流、DOA、人臉特徵 | 輕、可直接拿到麥克風陣列的方向資訊、與導航整合容易 | AIOS 核心要新增非瀏覽器終端的連線方式，工作量在 AIOS |

建議：**先做 A 的 spike**（在感知板上量 CPU、記憶體、延遲、喚醒率），達不到再走 B。感知板已決定用 Pi 4（ADR-0005），AIOS 的 rpi4 終端就是在 Pi 4 上跑 Chromium，可以直接借用；但鴨子的 Pi 4 還要跑導航，負載比 rpi4 終端重，spike 必須在導航同時運作的情況下量。兩條路線的對話語音都由 Mac 上的 Nous 處理，鴨子不跑大型語言模型或語音辨識。

## 3. 喚醒詞

- 鴨子有**自己的喚醒詞**（詞待使用者決定，例如鴨子的名字）。因為 sherpa-onnx KWS 是開放詞彙，新詞只要加設定與門檻，不用重新訓練；仍要在實際環境量測誤喚醒與漏喚醒。
- 喚醒偵測在**鴨子本機**常駐執行，未喚醒的音訊不寫檔、不上傳（沿用 AIOS 紅線）。
- **多台裝置的仲裁**：家裡會有 Mac、RPi、鴨子同時聽。規則草案：
  - 鴨子的喚醒詞 → 由鴨子回應；其他終端若也聽到，只回報「聽到鴨子的喚醒詞、音量多大」給核心，**不自己回應**，用來幫忙判斷叫的人在哪個房間（§4）。
  - 「Hey Nous」等原有喚醒詞 → 維持原有終端的行為；鴨子預設不回應，避免兩台同時回答。
  - 這需要 AIOS 核心新增「同一句喚醒只回應一次」的仲裁，屬於 AIOS 的批次。
- 走路時舵機與腳步噪音大，喚醒率會下降。鴨子走路中被叫醒時先停下來再聽。待機與在充電座上時喚醒率應最好；要實測。
- 鴨子自己說話時要避免自我觸發（AIOS 已有自我觸發防護，可沿用設計）。

## 4. 找人：被叫醒後走去找是誰叫它

```text
聽到喚醒詞
 ├─ 鴨子：停下 → 記錄聲源方向（麥克風陣列 DOA，換算到地圖座標）→ 回一聲「來了」
 ├─ 核心：聲紋辨認 → 可能是誰（或未知）
 └─ 其他終端：有沒有聽到、音量 → 推估在哪個房間
          ▼
判斷目標：
 ├─ 鴨子聽得清楚、方向明確 → 同一個房間：轉身面向聲源方向
 └─ 只有別的房間的終端聽得清楚 → 先導航到那個房間（ADR-0002）
          ▼
朝目標移動：一邊走一邊找人臉（感知板做偵測與特徵；比對送 Mac 核心，gallery 不離開核心）
          ▼
找到人：
 ├─ 臉部辨識結果與聲紋一致 → 確認是誰
 └─ 不一致或未知 → 「是誰叫我？」再聽一次，用新的聲源方向修正（可重複幾次）
          ▼
走到約 1 公尺、抬頭看著對方（頸頭俯仰）→ 開始對話
          ▼
逾時或找不到 → 停下，用語音誠實回報「我找不到是誰叫我」
```

細節與限制：

- **單一麥克風無法判斷方向**；DOA 需要麥克風陣列（ADR-0005 §2.2）。DOA 在房間內會受回音影響，只當方向參考，不當精確位置。
- 鴨子的鏡頭高度約 30～40 cm，大人的臉在 1.2～1.7 m；靠近時要抬頭，上游 `head_pitch`、`neck_pitch` 的角度範圍與鏡頭視角是否足夠，要在 P2 確認。
- 人坐著、躺著、背對鴨子時可能看不到臉；這時改以聲音互動確認，不硬找臉。
- 臉部辨識沿用 AIOS ADR-0001 的分工：特徵在終端算，**登記資料與比對留在 Mac 核心**；結果只有 matched／unknown／ambiguous。身分不等於授權。
- 門檻都未校準，數字要實測。

## 5. 情境範例：「去哥哥房間叫他起床」

由 Nous 編排（Nous 是大腦），鴨子執行各步並回報：

1. Nous 收到指令（或排程到點），呼叫 `app.duck.go_to {place: "brother_room"}`，得到任務 ID。
2. 鴨子導航；房門關著 → 停在門口回報，Nous 決定在門口叫還是放棄並告訴使用者。
3. 到達後 `app.duck.find_person {person: "brother"}`；人在床上可能看不到臉，改走到地圖上的 `brother_bedside`。
4. Nous 透過**鴨子終端**說話（即時語音工作階段改由鴨子的喇叭與麥克風進行），搭配天線、眼燈。
5. 聽回應（「好啦我起來了」），沒有回應就間隔重複，次數上限待定。
6. 結果**誠實回報**給下指令的人：「叫了三次，他回答『好』」或「沒有回應」。鴨子不能確認對方真的起床，只能說出觀察到的事。
7. 任務結束 → `app.duck.return_home`（ADR-0004）。

要讓第 4 步成立，AIOS 需要能把語音工作階段**指定到某一台終端**；這是 AIOS 的批次。

## 6. 隱私

可開關的隱私設定（全域、房間、家人、模式，以及誰能放寬）見 [ADR-0006](ADR-0006-privacy-settings.md)。以下是原則：

鴨子會帶著鏡頭與麥克風進出臥室，規則比固定終端更嚴格：

1. 沿用 AIOS 紅線：原始影像與未喚醒音訊**不寫檔、不進 trace、不外傳**。導航用的影像只在鴨子記憶體裡處理。
2. 鏡頭只在導航、找人、對話時開啟；待機與充電時關閉（喚醒詞只用麥克風）。開啟時用眼燈或其他可見方式提示。
3. 可以依房間設定規則，例如「哥哥房間只導航、不做臉部辨識」。
4. 送到 Mac 的是臉部特徵與聲紋特徵，不是影像或錄音（Wi-Fi 上的傳輸要加密，例如走 SSH 通道）。
5. **公開 repo 中不出現家人真實姓名、房間照片、平面圖或地圖資料**；文件只用 ID。
6. 帶看建圖錄下的影像只在 Mac 本機處理，建完圖後刪除原始影像（保留期限待使用者決定）。

## 7. 後果

- AIOS 端需要：非瀏覽器或無螢幕終端支援（路線 B 時）、多裝置喚醒仲裁、把語音工作階段指定到某台終端、接收鴨子事件。這些都是 AIOS repo 的批次，在 AIOS 完成並驗證前不宣稱可用。
- 鴨子端需要：`robot/audio/`（喚醒、DOA、音訊串流）、`robot/perception/`（人臉偵測與特徵）。
- 新工具：`app.duck.find_person`；`app.duck.announce` 視終端能力決定是否需要（見 [ADR-0001 §7](ADR-0001-duck-role-in-nous.md#7-2026-11-12-修訂行動夥伴)）。
