# ADR-0013：鏡頭常開與家庭監控

- 狀態：**部分採用**
  - §2「鏡頭預設常開」：使用者 2026-11-18 決定。
  - §2.2 夜間待在充電座時紅外線補光可以整晚開著、§2.3 渲染程式故障保護：2026-11-26 決定。
  - §3 家庭監控：2026-11-26 決定採用 **C「只回報文字事件」**；A（即時觀看）與 B（事件錄影）**不採用**。§3.2 是 C 的設計 v0，細節待決（§5）。
- 日期：2026-11-18（2026-11-26 修訂）
- 編號：原本在開發分支上編為 ADR-0007，因 v2 已有 [ADR-0007](ADR-0007-follow-me-and-wait-here.md)（跟著我來），2026-11-26 改為 ADR-0013（與 `claude/duck-companion-overnight` 分支的編號一致）。
- 相關：[ADR-0006](ADR-0006-privacy-settings.md)（隱私設定；本 ADR 修訂其 §5 的鏡頭預設）、[ADR-0002 §4.1](ADR-0002-indoor-localization-and-navigation.md#41-沒開燈時的備案紅外線補光2026-11-13-使用者同意以此為主)（紅外線補光）、[ADR-0004](ADR-0004-docking-and-charging.md)（充電座）、[ADR-0008](ADR-0008-single-board-pi4.md)（單板 Pi 4）、[眼睛設計](../eye_expressions.md)、[眼睛硬體 §1.3](../../hardware/expression_mods/gc9a01_eyes.md#13-硬體直連的鏡頭電源指示燈必做2026-11-18-使用者決定)（鏡頭電源指示燈）、根目錄 `CLAUDE.md` 隱私段

## 1. 背景

使用者 2026-11-18：「鏡頭我想要一直開著，他不是真的鴨子，當回到充電座時，還可以同時當家庭監控使用。」

這句話包含兩件不同的事：

1. **鏡頭一直開著**：影像仍然只在鴨子本機處理（AprilTag、人臉偵測、避障），不存、不外傳。這**不違反**現有的固定規則，只是改變 ADR-0006 §5 的預設值。
2. **家庭監控**：若是讓人**看到畫面**（即時或錄影），就會違反現有的固定規則：ADR-0006 §2.1 第 1 條（原始影像不寫檔、不傳出家裡）、第 2 條（送到 Mac 的只有特徵與結果），以及根目錄 `CLAUDE.md` 的隱私規則（沿用 AIOS 紅線）。

2026-11-26 使用者選了家庭監控的 C 方案：**只回報文字事件，不給人看畫面**。文字事件屬於「結果」，固定規則不用改。

## 2. 決定：鏡頭預設常開（2026-11-18）

### 2.1 內容

- ADR-0006 §5 的「鏡頭：只在導航、找人、對話、回充時開啟；待機與充電時關閉」改為「**鏡頭：常開**（包括待機與充電）」。
- 固定規則照舊：影像只在鴨子本機處理，**不寫檔、不進 trace、不外傳**；送到 Mac 的只有特徵與結果。
- 收緊的方式照舊（ADR-0006 §3）：任何人都可以用語音、實體按鈕或設定頁關掉鏡頭；夜間、訪客、完全隱私模式與房間設定仍然有效；實體隱私開關仍然直接斷電。「常開」只是預設值，不是不能關。

### 2.2 對其他設計的影響

| 項目 | 影響 | 處理 |
|---|---|---|
| 眼睛的狀態環 | 幾乎一直是青色 | 照實顯示；這就是 ADR-0006 要的「看得見的提示」 |
| 休息時的表情 | 閉眼睡著會讓人以為鴨子沒在看 | **鏡頭開著時不顯示閉眼**：休息用半垂眼的 `sleepy`，閉眼 `sleeping` 只在鏡頭關著時（[眼睛設計 §6](../eye_expressions.md#6-規則衝突時誰優先)，`policy.resting_expression` 有測試） |
| 硬體直連的鏡頭電源指示燈 | 一直亮 | 照實；燈的意義是「鏡頭有電」 |
| 紅外線補光 | 暗處會依 ADR-0002 §4.1.1 的規則自動開 | **夜間待在充電座時可以整晚開著**（2026-11-26 使用者決定）。發熱與耗電要量；充電座的位置不能讓紅外線照進臥室（§3.2 第 6 點） |
| Pi 4 運算、耗電、散熱 | 鏡頭解碼與偵測整天在跑；單板之後步態也在同一片 Pi 4（ADR-0008） | 未量測；ADR-0008 §2.5 的試用門檻量測要包含「待在充電座、鏡頭常開、監控事件偵測」的情況 |

### 2.3 渲染程式故障保護（2026-11-26 決定）

眼睛面板會一直顯示最後一幀；畫眼睛的程式當掉時，畫面可能停在「鏡頭關」。所以：

1. 眼睛渲染程式（`robot/eyes/`）每送出一幀就更新心跳，至少每 0.5 秒一次。
2. 鏡頭服務每 0.25 秒檢查一次；**超過 1.0 秒沒有心跳就停止串流**，向 Nous 回報 `eyes_renderer_down`。
3. 開機時鏡頭等渲染程式送出第一幀（狀態環已經畫好）之後才開始串流。
4. 渲染程式恢復後鏡頭自動恢復（因為預設常開）。
5. 後果要照實處理：鏡頭停了就不能導航，鴨子由安全模組停下站好，等渲染程式恢復；不假裝還在看路。

數字（0.5／0.25／1.0 秒）是起點，實作時依實測調整。**這條規則已決定，但程式還沒寫**：鏡頭服務尚未實作，心跳的介面和鏡頭服務一起做。

## 3. 家庭監控：採用 C「只回報文字事件」（2026-11-26）

### 3.1 三種做法與決定

| 做法 | 內容 | 是否要改固定規則 | 決定 |
|---|---|---|---|
| **C. 事件文字** | 鴨子在本機判斷，只回報**文字事件**，例如「14:05 客廳有人走動」；不給任何人看畫面 | **不用**：仍然只送結果 | **採用**（2026-11-26） |
| A. 家中即時觀看 | 透過 Nous（Mac）即時看鴨子的畫面，不錄影 | 要改 | 不採用 |
| B. 事件錄影 | A ＋ 偵測到事件時錄短片，存在 Mac | 要改 | 不採用 |

A、B 若之後要做，要另外決定並同時改 ADR-0006 §2.1 第 1、2 條、`CLAUDE.md` 隱私段、[雙目視覺規劃 §4](../stereo_vision_plan.md#4-做不到或刻意不做)，以及 AIOS 端；最少的保護是：鴨子身上看得出「有人在看」、觀看紀錄、只能經過 Nous、臥室浴室不看、訪客與完全隱私模式自動關、家人同意、不送雲端模型、錄影的保存與刪除規則。

### 3.2 C 的設計 v0（規劃中，未實作）

1. **只在充電座上監控**：鴨子接上充電座（充電觸點電氣確認，ADR-0004）、沒有任務、不在訪客或完全隱私模式時才產生監控事件。走動時不產生，避免變成「到處巡邏監看」。
2. **在鴨子本機判斷**：用 Pi 4 上的偵測結果產生事件；影像處理完就丟，不存、不外傳。
3. **事件只有文字與結構化欄位**，沒有影像、縮圖、人臉截圖或人臉特徵：

   | 事件 | 內容（範例） | 預設 |
   |---|---|---|
   | `person_motion` | 「14:05 客廳有人走動」：時間、地點 ID、持續秒數 | 開 |
   | `person_appeared`／`person_left` | 「21:30 客廳有人出現」「21:42 人離開了」 | 開 |
   | `light_changed` | 「23:10 客廳的燈被打開」（畫面亮度突然變化） | 開 |
   | `known_person_seen` | 「18:20 客廳看到 `brother`」（用 ID，名稱只在 Nous 本機對照） | **關**；要用臉部辨識，且該家人要同意參與辨識（ADR-0006 家人設定） |
   | `camera_blocked` | 「02:00 鏡頭被遮住或太暗，看不到」 | 開：讓監控紀錄誠實，不把「看不到」當成「沒事」 |
   | `monitor_paused`／`monitor_resumed` | 「09:00 監控暫停（訪客模式）」「11:30 恢復」：原因可以是訪客、完全隱私、實體開關、離開充電座、渲染程式故障 | 開：紀錄裡的空白段落要寫明原因 |

4. **合併與頻率**：同一地點連續的走動合併成一筆（5 分鐘內）；每小時事件上限（數字待定），避免洗版。
5. **送到哪裡**：只送 Nous（Mac）；紀錄存在 Nous 本機，保留天數待定。要不要推播到手機由 AIOS 端決定（不在本 repo 宣稱完成）。
6. **充電座的位置**：鏡頭朝向決定看得到哪裡。充電座不能朝向臥室、浴室的門口；夜間整晚開紅外線時也一樣。
7. **透明**：家人都看得到同一份事件紀錄；監控中狀態環照常是青色（不另加「有人在看」提示，因為沒有人在看畫面）。
8. **音訊不在 v0**：「玻璃破掉、很大聲」這類聲音事件要分析未喚醒的音訊，和固定規則的精神有衝突，v0 不做，要做另外決定。
9. **協定**：事件格式之後放進 `nous_duck/protocol/`（duck-link 批次），先改 schema 再改兩端。

## 4. 理由

- 鏡頭常開讓鴨子隨時能看路、認人、對準充電座；使用者也明確想要。
- 影像只在本機處理時，常開本身不增加外洩風險；風險來自「有人看畫面、畫面被存下來」，C 方案完全避開。
- C 方案得到大部分「看家」的價值（知道家裡發生什麼事、什麼時候），不用碰紅線。
