# ADR-0019：鴨子設定網頁與設定的單一來源

- 狀態：草案（Proposed）。程式第一版已實作（驗證層級見 [驗證紀錄](../validation/settings-2026-11-26.md)）；§5 的幾項要使用者決定
- 日期：2026-11-26
- 相關：[ADR-0001](ADR-0001-duck-role-in-nous.md)（安全判斷在鴨子本機）、[ADR-0006](ADR-0006-privacy-settings.md)（隱私設定；只能收緊）、[ADR-0009](ADR-0009-duck-link-transport-and-command-bridge.md)（duck-link）、[ADR-0010](ADR-0010-duck-voice.md)（語音）、[ADR-0013](ADR-0013-camera-always-on-and-home-monitoring.md)（鏡頭）、[ADR-0014](ADR-0014-duckd-head-direct-and-single-process.md)（duckd）、[ADR-0015](ADR-0015-gesture-library.md)（動作庫）、[ADR-0017](ADR-0017-audio-playback-path-v1.md)（音訊播放）
- 編號說明：ADR-0018 由 PR #37（充電座上的互動）使用，這份接在它後面

## 1. 背景

鴨子沒有螢幕。2026-11-26 做實機頭部與聽聲轉頭測試時，好幾個參數是 SSH 進 Pi 手改 JSON 的（麥克風方向、語音能量門檻 2e5、頭停穩等待 1.0 秒、正前方校正值）。可調的東西散在四個地方：

| 在哪 | 例子 | 怎麼改 |
|---|---|---|
| systemd 單元的命令列 | duckd 的 `--head-window-deg 15 --head-speed-deg 30` | 改 `/etc/systemd/system/duckd.service` |
| Pi 上的 JSON | `~/duck/doa/config/doa.json` | SSH 進去改，重啟服務 |
| 程式裡的常數 | `duckd/track.py`（死區、停穩、回正）、`duckd/presence.py`（表情對應、動作幅度）、`duck_audio/playback.py`（音量上限） | 改程式、重新部署 |
| 還沒有地方放 | 隱私開關（ADR-0006）、夜間時段、喚醒詞 | — |

完整盤點在 [`robot/settings/README.md`](../../robot/settings/README.md#盤點2026-11-26)。使用者要一個設定網頁（功能開關、語音設定、各種門檻、表情等）。

## 2. 決定

### 2.1 單一來源：一份 schema、兩個檔案

- **schema 在程式裡**：[`robot/settings/duck_settings/schema.py`](../../robot/settings/duck_settings/schema.py) 是唯一定義設定項目的地方。每一項有：key、型別、預設值、範圍（數字）或可選的值、說明、誰讀它（`consumer`）、怎麼生效（`apply`）、做到哪（`status`）、預設值與範圍的依據。`SCHEMA_VERSION` 從 1 開始。
- **值存在 Pi 的 `~/duck/settings/`**，只存「和預設不同、被設定過」的項目，所以之後改預設值，沒被動過的項目會跟著走：

| 檔案 | 內容 |
|---|---|
| `settings.json` | **使用者偏好**（功能開關、門檻、頭部動作、表情對應、隱私） |
| `calibration.json` | **機體量測值**（麥克風裝在哪、正前方校正值、角度方向、是否校正過） |
| `history/settings-NNNNNN.json` | 每次儲存前的上一版偏好，留最近 20 份 |
| `changes.jsonl` | 變更紀錄：時間、來源、哪一項從什麼改成什麼（ADR-0006 §3），留最近 500 筆 |
| `applied/<服務>.json` | 各服務回報「我現在實際在用的值」 |

- 檔案格式：`{"schema_version": 1, "revision": n, "updated_at": …, "updated_by": 來源, "values": {key: 值}}`。寫入是先寫暫存檔再改名（不會留下寫一半的檔案）。
- **驗證**：儲存時每一項依 schema 檢查型別與範圍；**超出範圍就拒絕並說明原因，不偷偷夾限**；一批裡有任何一項不合格就整批不寫。另有跨項目規則（目前一條：「頭停穩後等多久」要比「方位視窗」長 0.1 秒以上，否則頭會來回擺）。
- **讀取端再驗一次**：服務讀檔時用同一份 schema 檢查，檔案被手改成不合格的值就**不採用、退回預設值**，並把原因列在設定頁的「設定檔有問題」。檔案不存在或不是 JSON 也是退回預設，服務照常跑。

### 2.2 量測值和偏好分開

- 量測值（`kind: measurement`）描述的是「這隻鴨子怎麼組裝的」，偏好描述的是「使用者想要它怎麼表現」。兩者存不同的檔案。
- 「回復預設」「還原上一版」**不動量測值**。在設定頁改量測值要先勾「我確定要改量測值」。
- 量測值最好用量的：`python -m duck_audio.doa --calibrate 5 --write-config --settings-dir ~/duck/settings` 會把結果寫進 `calibration.json`（來源記為本機指令）。
- 舵機零點偏移（上游的 `~/duck_config.json`）**不搬進來**：它屬於舵機控制台，改它要人在場（§2.6）。

### 2.3 各服務怎麼讀到新值

所有服務都匯入同一份 `duck_settings`（Pi 上用一個 `.pth` 接進 `~/duck/duckd-venv`），只用標準函式庫。

| 服務 | 讀哪些 | 怎麼生效 |
|---|---|---|
| `duck-doa`（聲源方位） | 語音能量門檻、判斷語音的方式、方位視窗、最少樣本數、分群角度；量測值四項；隱私「讀取聲源方向」 | **即時**：每秒看一次檔案有沒有變（比對修改時間與大小），變了就換，不用重啟 |
| `duckd` | 功能開關（聽聲轉頭、具名動作、對話小動作、說話點頭）、聽聲轉頭的停穩／回正／死區／信心、對話小動作幅度、presence 對應的表情 | **即時**（同上，每秒一次） |
| `duckd` | 頭部最高角速度、頭部活動範圍 | **要重啟 duckd**：這兩項進了安全仲裁器的 `Limits`（凍結的資料），執行中不換 |

- **「已生效」不是用猜的**：每個服務套用後把實際在用的值寫到 `applied/<服務>.json`（含行程 pid）。設定頁拿它和設定值比：相同且行程還活著 →「已生效」；不同且那一項要重啟 →「要重啟 duckd 才生效（現在用的是 30）」；行程不在 →「沒在跑；下次啟動時會用這個值」；服務在跑但沒有回報 →「還是舊版程式」。
- 設定頁**不會**替你重啟服務：重啟 duckd 會讓頭回到接手位置並放開匯流排，這是有人在旁邊才該做的事。頁面只告訴你要重啟。
- 讀不到設定（`duck_settings` 沒裝、資料夾讀不到）時：duckd 的頭部限制退回 30°/s、±15°（2026-11-25 無人看顧時的規定值，和 schema 預設相同），其他用內建預設；`duck-doa` 退回原本的 `doa.json`。
- duckd 命令列的 `--head-speed-deg`、`--head-window-deg` 有給時仍以命令列為準（測試腳本在用），回報的也是實際在用的值。

### 2.4 網頁跑在哪、誰連得到

- 跑在 Pi 上的獨立服務 `duck-settings`（`python -m duck_settings`，只用標準函式庫），埠 **8081**（舵機控制台是 8080）。不放進 duckd：設定頁掛掉不能影響控制迴圈，duckd 沒在跑時也要能改設定。
- systemd 單元加 `PrivateDevices=true`、`ProtectSystem=strict`、`ReadWritePaths=~/duck/settings`：這個服務**看不到任何硬體裝置**（舵機匯流排、I2C、GPIO、USB），只能寫自己的設定資料夾。
- 存取範圍比照舵機控制台（使用者 2026-11-25 決定家裡區網內不需要 token）：
  - 綁所有介面，但**伺服器只接受區網內的來源位址**（loopback、私有網段、link-local），其他回 403。
  - 寫入要帶自訂標頭與 JSON：別的網站沒辦法叫你的瀏覽器跨站送出。`Host` 標頭要是 IP、`*.local`、`localhost` 或主機名稱（擋 DNS rebinding）。
  - **不新增任何帳號或密碼**。可選的 `--require-token`（部署時 `SETTINGS_REQUIRE_TOKEN=1`）和控制台同一種做法。
- 部署腳本預設**不 enable、不啟動**（`deploy_settings.sh`；`--start` 啟動、`--enable` 開機自動啟動）。
- 頁面是單一 HTML，樣式與程式全部內嵌，不從網路載入任何東西；CSP 設成只能連回自己。手機寬度可用。

### 2.5 隱私設定：這一頁只能收緊

ADR-0006 §3：收緊誰都可以；放寬只能在 Mac 上的 Nous 設定頁（那一頁還沒做），不接受語音或模型放寬。鴨子設定頁在區網內沒有登入，等於「家裡 Wi-Fi 上的任何人」，所以**保守處理**：

| 來源 | 誰 | 隱私設定 |
|---|---|---|
| `web` | 鴨子設定頁 | **只能收緊**。放寬的請求一律拒絕（直接打 API 也一樣），並告訴你本機指令怎麼下 |
| `duck_link` | Nous／模型（這條路還沒有，見 §2.7） | 只能收緊 |
| `local_cli` | 登入鴨子本機的人（要 SSH 金鑰）：`~/duck/settings/duck-settings set <key> <值>` | 可以放寬 |

- 「回復預設」「還原上一版」如果會放寬隱私，那一項略過並回報。
- **規則在資料產生處執行**（ADR-0006 §4）：目前唯一接上的隱私開關是「讀取聲源方向」。關掉後 `duck-doa` 放開 USB 裝置、不再對麥克風送任何請求，只回報自己被關掉；不是「讀了再丟」。
- ADR-0006 §2.1 的固定規則（原始影像與未喚醒音訊不寫檔不外傳、鏡頭開著一定有提示…）在頁面上列出來，**沒有開關**。
- 其餘隱私項目（模式、鏡頭、常駐聆聽、臉部辨識）顯示但停用，標「規劃中／硬體未到」。

### 2.6 不能出現在設定頁上的東西

| 不上頁面 | 在哪 |
|---|---|
| 緊急停止、解除緊急停止 | `duckd-ctl estop`／`clear-estop`（本機）、舵機控制台 |
| 過熱、低電壓、跌倒、通訊中斷的門檻與保護；關掉任何安全保護 | `duckd/limits.py`、舵機控制台的程式；要改走 ADR 與驗證紀錄 |
| 頭部角度的機構上限、角速度硬上限（90°/s） | `duckd/limits.py`。設定頁的角速度最多 60°/s、活動範圍 ±5～30°，都在硬上限以內；「不設活動範圍」不提供 |
| 腿的任何設定、扭力、kp、零點偏移 | 舵機控制台（要人在場） |
| 接手／釋放舵機匯流排、啟動停止服務 | `duckd-ctl engage`／`release`、`systemctl`（本機） |
| 隱私固定規則的開關、在這一頁放寬隱私 | 沒有開關；放寬走本機指令（§2.5） |

寫成程式與測試：schema 的 key 不能含 `safety`、`estop`、`torque`、`leg`、`kp`、`offset`、`temp`、`volt`、`walk` 等字；設定的上限低於 duckd 的硬上限；API 不接受 schema 以外的 key。

**不做假開關**：`status` 是「規劃中」或「硬體未到」的項目在頁面上看得到（知道以後會有什麼），但控制項停用、標明卡在哪，而且**任何來源都寫不進去**。

### 2.7 和 Nous 的關係

- 設定頁是鴨子的**本機**工具，不經過 duck-link，也不是 Nous 的能力。Nous 不知道也不需要知道這一頁。
- 之後 Nous 可以經 duck-link 讀設定、並在使用者要求時**收緊**（「鴨子，不要再轉頭了」）。只先寫提案：[`protocol/proposals/e-settings-over-duck-link.md`](../../protocol/proposals/e-settings-over-duck-link.md)，**沒有改 schema**。儲存層已經有 `duck_link` 這個來源與它的規則（隱私只能收緊、不能改機體量測值、未實作的項目不能寫），但**沒有任何程式會用這個來源呼叫**。
- ADR-0006 說隱私設定「存在 Nous 本機，同步到鴨子」。這一版相反：值存在鴨子上。等 Nous 的設定頁與 `privacy_policy` 同步做出來時，隱私那一區要改成以 Nous 的為準、鴨子存「最後一次確認過的版本」；其餘（門檻、表情、量測值）留在鴨子上。這是待決（§5）。

## 3. 理由

- **為什麼不讓每個服務各自留設定檔、網頁去改各個檔**：範圍檢查會散在各處，網頁要懂每個檔的格式；現在一個 schema 同時給網頁（顯示、驗證）和服務（讀取時再驗）用。
- **為什麼值存檔案、不經過某個常駐程式轉發**：服務之間只共用檔案，設定頁沒在跑時服務照樣讀得到；`duck-doa` 與 duckd 互不依賴。每秒 `stat` 兩個檔案的成本可以忽略。
- **為什麼超出範圍是拒絕而不是夾限**：使用者拿手機對著鴨子調，夾限會讓「我設 90、它其實 60」變成看不到的落差。
- **為什麼隱私只能收緊**：見 §2.5。代價是在頁面上關掉之後要 SSH 才能打開，這是刻意的，但要使用者確認（§5.1）。
- **為什麼設定頁不能重啟 duckd**：重啟會動到頭；會讓東西動的操作留在本機指令。

## 4. 後果

- 改到的既有檔案（範圍刻意小）：`duck_audio/doa.py`（`--settings-dir`、執行中換設定、關閉時不讀裝置）、`duckd/core.py`（`apply_settings`、三個功能開關的判斷、表情對應）、`duckd/presence.py`（`head_target` 多三個參數）、`duckd/__main__.py`（`--settings-dir`、每秒輪詢）、`duckd/localctl.py`（`express` 本機預覽、`status` 多兩欄）、`duckd/_paths.py`、`deploy_duckd.sh` 與 `setup_doa.sh` 的 `ExecStart`。沒有 `--settings-dir` 時，兩個服務的行為和以前一樣。
- `duckd.service` 不再把 `--head-window-deg 15 --head-speed-deg 30` 寫死，改讀設定（預設值相同；讀不到時也是這兩個值）。
- 第一次部署會把 Pi 上手改過的 `doa.json` 搬進設定（`import-doa`）；之後 `doa.json` 只在設定讀不到時當備援。
- duckd 多一個本機指令 `express`（預覽表情，最多 10 秒）。它不套用「Nous 能叫哪些表情」的限制，因為是站在鴨子旁邊的人在看樣子；presence 對應表情的選項則有限制（代表實際狀態的表情不能指給別的狀態）。
- 「語音與聲音」整區目前只能看：喇叭播放路徑還沒接成常駐服務，沒有程式會讀這些值。

## 5. 待決（要使用者決定）

1. **在設定頁放寬隱私**：現在不行，要 SSH 下指令。可選：(a) 維持；(b) 允許設定頁放寬，但要先開 token；(c) 等 Nous 的設定頁。
2. **存取**：現在區網內不需要 token（比照舵機控制台）。設定頁能關功能、收緊隱私、改門檻，但不能讓鴨子做出不安全的動作。要不要預設開 token？
3. **開機自動啟動**：部署腳本預設不 enable。要不要讓設定頁開機就起來？
4. **頭部的可調範圍**：角速度 5～60°/s、活動範圍 ±5～30°。要不要放寬到硬上限 90°/s、或提供「不設活動範圍」？需要先有模擬或實機量測（ADR-0015 §2.3）。
5. **隱私設定存哪邊**（§2.7）：等 Nous 設定頁時再定。
6. 設定頁要不要有「重啟 duckd」的按鈕（要給服務 sudo 權限，而且頭會動）。建議不要。
