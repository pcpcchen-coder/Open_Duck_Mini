# ADR-0012：鴨子的記憶系統＝沿用 Nous 記憶層，鴨子只補「身體、空間、任務」記憶

- 狀態：**草案（Proposed）**，待使用者決定 [§11](#11-待決需要使用者決定)
- 日期：2026-11-17
- 相關：[ADR-0001](ADR-0001-duck-role-in-nous.md)（Nous 管記憶）、[ADR-0002](ADR-0002-indoor-localization-and-navigation.md)（地圖）、[ADR-0003](ADR-0003-mobile-terminal-wake-and-find.md)（行動終端、找人）、[ADR-0006](ADR-0006-privacy-settings.md)（隱私設定）、[路線圖](../roadmap.md)
- AIOS 參考（唯讀，main `7b0257d`）：`docs/16_Nous_Memory_Layer_Design_2026-10-26.md`、`docs/adr/ADR-0002-nous-family-memory.md`、`docs/02_OSS_Component_Map.md`、`prototype/ambient-shell/server/memory/`

## 0. 一頁摘要

使用者的問題：鴨子的記憶要做成 Hermes 那種系統，還是找其他套件來建？

**建議：兩個都不要當主體。**

1. **家人記憶不要在鴨子上另外做一套。** Nous 已經有自己的家庭記憶層（AIOS `MemoryService`，MEM-0～MEM-5b）：記憶分人物保存、有來源、能更正和忘記、加密、能撤銷已送出的上下文。鴨子是 Nous 的一個終端，直接用同一套就好。另做一套 Hermes 式記憶，家裡就會有兩份互相矛盾的「家人資料」，也會把家人資料放到一台會被帶著走、可能被拆開的機器人身上。
2. **外部記憶框架（mem0、Letta、Zep／Graphiti、Honcho）也不要當主體。** AIOS 在 2026-10 已經評估過，結論是它們不能取代 Nous 的人物歸屬、寫入授權、撤銷與隱私規則（AIOS ADR-0002）。本 ADR 沿用這個結論。
3. **鴨子真正缺的是機器人才有的記憶**，這是 Nous 現在沒有的，也是本 ADR 的主要內容：
   - **身體記憶**：跌倒、過熱、低電壓、舵機錯誤、電池循環（存在鴨子本機，不含個人資料）。
   - **空間記憶**：地圖、地點、禁區、AprilTag（以 Nous 為準，鴨子保存唯讀副本）。
   - **任務與事件歷程**：去過哪裡、成功或失敗、為什麼失敗（存在 Nous，加密）。
   - **例行任務**：例如「叫哥哥起床」的步驟（存在 Nous，由使用者建立或核准）。
4. **從 Hermes 借四個好點子**，但用 Nous 的規則改寫（§4）：常駐少量重點、環境筆記、可搜尋的歷程、把做過的流程存成可重用的程序。

> 名稱提醒：Hermes Agent 是 Nous Research 公司的開源 agent，和本專案的 Nous（AIOS）無關，只是名字相同。

## 1. 背景

### 1.1 Nous 已經有的記憶層

依 AIOS `docs/16` 與 AIOS ADR-0002（唯讀查閱 `7b0257d`）：

| 項目 | AIOS 現況 |
|---|---|
| 擁有者 | Mac 上的 Nous 核心；`MemoryService` 是唯一寫入入口，模型不能直接寫 |
| 分層 | 當次上下文、個人偏好（每位家人分開）、家庭共用事項、工作摘要與決定 |
| 寫入 | 只有使用者明確說「記住」（核心發 `SourceTicket`）才寫；模型自己說的話、電視聲音、轉述不能建立記憶；MEM-5a 的自動建議預設關閉，只提出候選 |
| 儲存 | 加密快照（AES-256-GCM，金鑰在 macOS Keychain），單一寫入者、原子保存 |
| 取用 | 先依人物與同意過濾再排序；新通話最多帶 4 筆常駐，單次最多 8 筆、4 KB |
| 忘記 | 刪除資料，並撤銷已帶著舊內容的對話（語音會重建通話） |
| 外部框架 | 2026-10 的 OSS 地圖曾把 Letta 列為主選、mem0 為備選；之後 AIOS ADR-0002 決定首版不用外部記憶框架 |
| 驗證層級 | MEM-1～MEM-5b 程式完成、雲端（Linux）測試通過；**Mac gate 未執行**，AIOS 自己也不宣稱真機可用 |

### 1.2 Hermes Agent 的記憶設計（摘要）

依 2026-11 公開的第三方介紹文章整理，**沒有讀官方原始碼**，細節（例如字數上限、檔案路徑）採用前要再查官方文件：

| 機制 | 作法 |
|---|---|
| `MEMORY.md` | agent 自己的筆記：環境事實、慣例、工具的小毛病；有字數上限（約 2,200 字元） |
| `USER.md` | 使用者輪廓與偏好；有字數上限（約 1,375 字元） |
| 載入方式 | 每次對話開始時把兩個檔案貼進 system prompt，整段對話中保持不變 |
| 寫入方式 | 模型呼叫 `memory` 工具做 add／replace／remove，模型自己判斷什麼值得記 |
| 歷程搜尋 | 每段對話記進 SQLite，用 FTS5 全文索引；`session_search` 工具按需查舊對話 |
| Skills | 從完成的任務整理出可重用的程序，之後找到更好做法或被使用者糾正時更新 |
| 外掛 | 可另接外部記憶服務（例如 Honcho、mem0） |

Hermes 的設計目標是**一位使用者、一台電腦上的個人 agent**，記憶由模型自己整理。

### 1.3 鴨子的限制

| 限制 | 對記憶的影響 |
|---|---|
| 身體板 Pi Zero 2 W（512 MB）、感知板 Pi 4 忙著導航、喚醒詞、人臉（ADR-0005） | 鴨子上不能跑語言模型、向量資料庫或常駐記憶服務 |
| 鴨子會進臥室、可能被帶出門或拆開 | 鴨子上不應該存家人偏好、對話內容、行蹤歷史 |
| AIOS 紅線：原始影像與未喚醒音訊不寫檔、不進 trace、不外傳 | 記憶的來源不能是錄音或影像 |
| 安全只在鴨子本機（ADR-0001） | 記憶或模型學到的東西不能改 safety 的上限、禁區或白名單動作 |
| 兩邊只透過 duck-link 協定溝通 | 記憶相關的資料交換也要寫進 `protocol/` 的 schema |

## 2. 決定

1. **不在鴨子上建第二套 Hermes 式記憶，也不用外部記憶框架當家人資料的來源。**
2. **家人記憶一律由 Nous `MemoryService` 管。** 鴨子終端是 `MemoryService` 的一條新路徑（AIOS 批次）；記憶內容只送給 Mac 上的模型，**不送到鴨子、不存在鴨子上**。鴨子只負責收音、播放，聽到的是 Nous 生成的語音。
3. **鴨子新增的記憶分成六層**，每層的擁有者、位置、寫入者、保存期限都寫清楚（§3）。
4. **借 Hermes 的好點子，但不借它的寫入方式**：模型不能自己決定寫入；記憶來源要能追溯；不保存整段對話（§4）。
5. 本 ADR 是對 ADR-0001「記憶：Nous ✅、鴨子 ✗」的補充：家人記憶仍然是 ✗；鴨子本機只多了**不含個人資料的身體記憶**、**地圖副本**與**只在 RAM 的工作記憶**。

## 3. 記憶分層

| 層 | 內容（例子） | 擁有者與位置 | 會不會留下 | 誰能寫 | 模型看得到什麼 |
|---|---|---|---|---|---|
| **L0 工作記憶** | 目前任務、最近幾次的聲源方向、剛剛在哪裡看到臉（地點＋時間＋Mac 回傳的比對結果） | 鴨子感知板，**只在 RAM** | 不寫檔；短時間後清掉（時間待定，例如 5 分鐘） | 鴨子程式 | 看不到；只透過 `mission_status`、`where` 的結果間接得知 |
| **L1 身體記憶** | 跌倒、被抱起、過熱、低電壓、舵機錯誤、通訊中斷的紀錄；電池循環、舵機累計運轉、校正版本 | 鴨子本機（身體板為主） | 會；有容量上限、循環覆寫 | 鴨子程式（safety 先停再記） | 只有 `status` 的摘要（例如「本週跌倒 2 次」） |
| **L2 空間記憶** | AprilTag ID 與位姿、地點（只有 ID）、房間連通、門、禁區、樓梯口 | **以 Nous 為準**（Mac 建圖工具產生）；鴨子保存最後確認過的唯讀副本 | 會；版本化 | 只有使用者在 Mac 上用建圖工具改 | 地點 ID 與 Nous 本機的顯示名稱 |
| **L3 任務與事件歷程** | 任務 ID、類型、目標地點 ID、（可選）家人 ID、開始與結束時間、結果代碼與原因（`door_closed`、`lost`、`low_battery`…） | Nous，加密保存（沿用 AIOS 受保護任務儲存） | 會；保存期限待決（建議 30 天） | Nous 核心依 duck-link 事件寫入；模型不能寫 | 依查詢回傳的精簡紀錄 |
| **L3b 環境筆記** | 「近 14 天，22:00 後 `brother_room` 的門 6 次中有 5 次關著」「`kitchen` 附近 3 次迷路，建議多貼一張 AprilTag」 | Nous；**由 L3 用固定程式統計出來**，不是模型寫的 | 跟著 L3；L3 刪除時一起刪 | 統計程式 | 筆記內容＋樣本數＋統計期間 |
| **L4 家人記憶** | 偏好（「叫我起床前先放音樂」）、家庭共用事項 | **Nous `MemoryService`（既有）** | 依 AIOS 規則 | 只有使用者明確說「記住」 | 依 AIOS 規則（人物、同意、筆數上限） |
| **L5 例行任務（程序記憶）** | 「叫哥哥起床」：`go_to brother_room` → `find_person` → 說話 → 聽回應 → 最多重複 3 次 → `return_home` | Nous（P7 的排程與任務） | 會；版本化，看得到上次修改時間 | 使用者建立；Nous 可以**提出**修改建議，使用者按下確認才生效 | 例行任務的步驟 |

刻意**不做**（要做必須另立 ADR）：

| 項目 | 原因 |
|---|---|
| 家人的行蹤歷史（誰幾點在哪個房間） | 比偏好更敏感；L0 只在 RAM 保留幾分鐘，給找人用 |
| 物品位置記憶（「遙控器上次在哪」） | 要在鴨子上做物體辨識，並決定哪些物品可以記；[雙目視覺規劃 §4](../stereo_vision_plan.md#4-做不到或刻意不做) 已規定未經 ADR 不做 |
| 保存整段對話逐字稿、錄音、影像 | AIOS 紅線；AIOS 也不把整段聊天當記憶來源 |
| 推測家人的性格、心情、關係 | AIOS docs/16 §1：首版只做可追溯的偏好，不推測 |
| 模型自己寫新的動作、改 safety 參數 | 安全只在鴨子本機；動作只能從鴨子回報的白名單選 |

### 3.1 各層的技術選擇

| 層 | 建議 | 理由 |
|---|---|---|
| L0 | Python 程式內的資料結構，附到期時間 | 不需要資料庫；**感知板要關掉 swap 或改用加密 swap**，否則「只在 RAM」的資料可能被換頁寫到 SD 卡 |
| L1 | JSON Lines 追加寫入＋依大小輪替（容量上限暫定 2 MB，待量測） | 斷電時最多壞最後一行，讀的時候丟掉；少寫入，SD 卡壽命比較好；Python 標準函式庫就夠，不用新依賴。只有安全事件立即 `fsync` |
| L2 | 一個版本化的地圖包（JSON，附版本號與 SHA-256），schema 放 `protocol/` | 鴨子開機時驗證雜湊，只用最後確認過的版本；地圖包裡**沒有影像** |
| L3 | 沿用 AIOS 已有的受保護任務儲存（MEM-4a 的 sealed vault）與 MEM-4c 的搜尋索引 | 不新增第二種加密儲存；L3 可以當成 MEM-4c 搜尋的另一個來源 |
| L3b | Nous 核心的固定統計程式（TypeScript），結果附 `derived_from` | 可重算、可測試；來源刪除時一起刪（同 MEM-5b 的作法） |
| L4 | 既有 `MemoryService`，不改形狀 | — |
| L5 | 結構化的步驟清單（只能引用已註冊的工具 ID），存在 AIOS 的任務與排程 | 執行時每一步仍走 `app.duck.*` 與鴨子的 safety |

## 4. 對照 Hermes：借什麼、不借什麼

| Hermes 的做法 | 對鴨子的判斷 | 改寫後 |
|---|---|---|
| `USER.md` 有字數上限，每次對話都帶 | **借**：少量常駐、其餘按需取用是好做法 | AIOS 已經有：常駐最多 4 筆、單次最多 8 筆／4 KB；而且分人物 |
| `MEMORY.md` 記環境事實與工具的小毛病 | **借**：鴨子很需要「這個家的環境筆記」 | 改成 L3b：**由任務紀錄統計**，附樣本數；不讓模型自由寫 |
| 模型自己決定 add／replace／remove | **不借** | 寫入要使用者明確指示（AIOS `SourceTicket`）；模型只能提出候選（MEM-5a） |
| 單一使用者 | **不借** | 家裡有多位家人，記憶要分人物；辨識出是誰不等於授權 |
| 整段對話記進 SQLite＋FTS5 | **一半借** | 不存逐字稿；只把**任務與事件**存成 L3，用 MEM-4c 的索引搜尋 |
| 對話開始時把記憶固定在 system prompt | **不借** | 忘記或換人時要能撤銷已帶進去的內容（AIOS 會重建語音通話） |
| Skills：從完成的任務自動整理、自動更新程序 | **一半借** | L5 例行任務：Nous 可以根據 L3 的結果**建議**修改（「最近三次都叫 3 次才醒，要不要改成先放音樂？」），使用者確認才生效；不能新增動作或改安全參數 |
| 記憶以明文檔案放在家目錄 | **不借** | 家人資料加密（AIOS）；鴨子上不放家人資料 |

## 5. 套件評估

本表只比較**設計上是否相容**；授權、版本與維護狀態在真的採用前要再查官方 repo。

| 選項 | 是什麼 | 優點 | 不適合當主體的原因 | 可以用在哪裡 |
|---|---|---|---|---|
| 自建 Hermes 式（Markdown＋SQLite FTS5＋skills） | 照 Hermes 的形狀自己寫 | 簡單、看得懂 | 和 AIOS 記憶層重複，兩份家人資料會互相矛盾；單一使用者；模型自己寫；存逐字稿 | 不建議 |
| 直接跑 Hermes Agent | 完整的 agent 執行環境（Python） | 現成、社群活躍 | 等於換掉 Nous 的 agent；工具、確認語意、隱私規則都要重來，違反 ADR-0001 的分工 | 不建議 |
| mem0 | 用語言模型自動從對話抽出事實，存進向量資料庫 | 自動化程度高、API 簡單 | 自動抽取和「明確說記住才寫」衝突；預設用雲端模型與 embedding；不處理人物歸屬與撤銷 | 不建議 |
| Letta（MemGPT 後繼） | 有狀態的 agent 伺服器 | 分層記憶概念完整 | AIOS 2026-10 原本列為主選，之後 ADR-0002 決定不採；多一個常駐服務 | 不建議 |
| Zep／Graphiti | 有時間軸的知識圖譜 | 適合「什麼時候發生什麼」的查詢 | 要另跑圖資料庫；目前資料量（AIOS 上限 1,000 筆）用不到 | L3 資料變多、需要時間關聯查詢時再評估 |
| Honcho | 使用者建模服務（Hermes 可選外掛） | 能整理出使用者輪廓 | 會推測個性與心理狀態，和 AIOS「不推測」的規則衝突 | 不建議 |
| SQLite（Python 標準函式庫）、JSON Lines | 基本元件 | 不用新依賴、可離線、好測試 | — | L1 |
| 本機 embedding＋sqlite-vec 等向量索引 | 語意搜尋 | 中文同義詞召回比較好 | 只是索引，不是資料來源 | AIOS 的中文測試集若顯示召回不足，當成 `MemoryService` 後面可重建的索引 |

結論：**記憶的規則和資料來源自己掌握（沿用 AIOS），外部套件最多當可替換的索引元件。** 這和 AIOS ADR-0002 的取捨一致。

## 6. 資料流範例

### 6.1 「叫哥哥起床」（R-001 S1）

```text
排程到點：L5 例行任務 wake_brother（使用者建立的 v3）
 → app.duck.go_to {place: "brother_room"}：鴨子用 L2 地圖副本導航
     鴨子：L1 記錄電量；L0 保存目前任務
     事件 mission_progress / mission_done → Nous 寫入 L3
 → app.duck.find_person {person: "brother"}：臥室臉部辨識預設關（ADR-0006）→ 走到 brother_bedside
 → 依 L5 的步驟先放音樂、再透過鴨子終端說話
     要取用 brother 自己的偏好（L4），要依 AIOS 規則先選定人物（認出聲音後問一句）；沒選定就只用全家共用的記憶
 → 結果寫入 L3：「叫了 3 次，回答『好』」；誠實回報給下指令的人
 → app.duck.return_home；L1 記錄充電開始（以電氣訊號為準）
之後：L3b 統計「最近 5 次平均要叫 2.6 次」→ Nous 提出修改 L5 的建議 → 使用者確認才改
```

### 6.2 「鴨子，你今天做了什麼？」

Nous 查 L3（今天的任務與事件）回答；沒有紀錄就說不知道，**不編造**。鴨子本身不用回答這題，鴨子上也沒有這些資料。

### 6.3 斷線時的事件

```text
Wi-Fi 斷線 → 鴨子停下站好（S5）；事件照樣產生，暫存在跑 nous_link 的那塊板子上
 每個事件帶 boot_id＋seq（開機識別＋遞增序號）
重新連線 → 鴨子補送 → Nous 依 (boot_id, seq) 去重後寫入 L3 → 回 ack
暫存滿了 → 補送時附「丟掉 N 筆」，Nous 照實記錄，不假裝完整
```

## 7. 對 duck-link 協定的影響（規劃中）

1. `event` 訊息加 `boot_id`、`seq`，Nous 回 ack；補送要冪等。
2. 新增 `map_package` 文件（版本、SHA-256、Tag、地點 ID、連通、禁區），由 Nous 推給鴨子；鴨子回報目前使用的版本。版本不符或雜湊錯誤時，導航類工具回 `refused`（原因代碼例如 `map_mismatch`，代碼清單待定）。
3. `app.duck.places` 建議改成**鴨子只回地點 ID 與地圖版本**，顯示名稱由 DuckAdapter 從 Nous 本機設定補上，讓鴨子上完全沒有家中的命名資料。這是對 ADR-0001 §7.3 的建議修訂，待決。
4. **協定裡沒有任何傳送家人記憶給鴨子的訊息。** 這一點要寫進 `protocol/` 的 README，之後加訊息時當成檢查項目。
5. 任務歷程（L3）的查詢由 Nous 核心提供，**不是 `app.duck.*` 工具**，因為資料不在鴨子上；工具名稱在 AIOS 決定。

## 8. 隱私

ADR-0006 的固定規則全部適用。本 ADR 另外建議（需要使用者同意後才寫進 ADR-0006）：

| 新開關 | 建議預設 | 關掉的代價 |
|---|---|---|
| 保存任務歷程（L3） | 開，保留 30 天 | 不能回答「今天做了什麼」，也沒有環境筆記 |
| 歷程中記錄對象是誰（家人 ID） | 開 | 只記地點和結果，不知道當時找的是誰 |
| 環境筆記（L3b） | 開 | Nous 不會根據過去經驗調整計畫或提醒你補貼 AprilTag |
| 鴨子終端取用家人記憶（L4） | 跟 Nous 的記憶設定；**訪客模式下不取用**；夜間模式不唸出記憶內容 | 在鴨子旁邊對話時，Nous 不會用你交代過的偏好 |
| 在鴨子旁邊用語音寫入記憶 | **關**，量測誤存率後再決定 | 要到 Mac 或 RPi 終端說「記住」 |

- 「你記得我什麼？」在鴨子旁邊問時，建議改到有螢幕的終端顯示清單，而不是用鴨子的喇叭整份唸出來，因為旁邊可能有其他人。
- 刪除一位家人的資料時，L3 中帶這個家人 ID 的紀錄與相關的 L3b 筆記要一起刪除，或拿掉 ID（二選一，待決）。
- 模型只能收緊、不能放寬（ADR-0006 §3），這幾個開關也一樣。

## 10. 後果

- 鴨子上不需要記憶框架、向量資料庫或語言模型；本 repo 的記憶工作主要是 `robot/` 的身體日誌、`protocol/` 的事件序號與地圖包。
- 大部分記憶功能要在 AIOS 完成：鴨子終端的記憶路徑、任務歷程、環境筆記、例行任務。要加進[路線圖的 AIOS 批次](../roadmap.md#aios-端需要的批次在-aios-repo-進行)。在 AIOS 完成並驗證前，本 repo 不宣稱鴨子「記得」任何事。
- 跟著 AIOS 的記憶層演進：AIOS 若之後改用 SQLite 或加入語意索引，鴨子這邊不受影響，因為鴨子不碰家人記憶。
- 代價：沒有 Nous 時鴨子什麼都不記得（只剩身體記憶與地圖），這是刻意的取捨，符合「Nous 是大腦，鴨子是身體」。

## 11. 待決（需要使用者決定）

1. **方向**：同意「不另做 Hermes 式記憶、沿用 Nous 記憶層、鴨子只補身體／空間／任務記憶」嗎？
2. **鴨子旁邊能不能用語音寫入記憶**：建議先只讀（MD-3），MD-5 量測誤存率後再決定。
3. **任務歷程保存多久、要不要記錄對象是誰**：建議 30 天、記錄家人 ID。
4. **刪除家人資料時，任務歷程要刪除還是拿掉 ID**。
5. **環境筆記**預設開還是關。
6. **地圖副本要不要在鴨子上加密**：加密的話地圖被偷也看不懂，但鴨子開機時要先連上 Nous 拿金鑰才能導航（Nous 不在時鴨子不能走）。建議先不加密，地圖包裡沒有影像也沒有名稱，只有 ID 與座標。
7. **`app.duck.places` 是否改成只回 ID**（§7.3）。
8. 物品位置記憶要不要列入之後的計畫（要做須另立 ADR）。
