# ADR-0006：可開關的隱私設定

- 狀態：**部分採用**：使用者 2026-11-12 要求「隱私規則設計成可以開關設定」，同意 §5 的建議預設值，並決定**加裝實體隱私開關**、**用眼燈顏色提示鏡頭狀態**；2026-11-17 眼燈改為**兩片 1.28 吋圓形螢幕**，並採用「只畫合成圖形」「螢幕不能顯示就不開鏡頭」「加裝硬體直連的鏡頭電源指示燈」三項（§4.2）
- 日期：2026-11-12
- 相關：[ADR-0003 §6](ADR-0003-mobile-terminal-wake-and-find.md#6-隱私)（隱私原則）、[ADR-0002](ADR-0002-indoor-localization-and-navigation.md)（導航需要鏡頭）、AIOS CLAUDE.md 產品紅線、AIOS ADR-0001（身分不等於授權）

## 1. 背景

鴨子會帶著雙目鏡頭與麥克風陣列在家裡走動，包括進入臥室。不同家人、不同房間、不同時段的期待不一樣，所以隱私規則要能**開關與調整**，而不是寫死。

難處是**隱私開關會影響功能**：鏡頭關掉就不能導航（ADR-0002 靠視覺定位），臉部辨識關掉就只能用聲音找人。設定介面必須讓使用者看到每個開關的代價。

## 2. 決定：兩層規則

### 2.1 固定規則（不能關）

這些是 AIOS 的產品紅線或安全規則，**沒有開關**：

1. 原始影像與未喚醒的音訊**不寫檔、不進 trace、不傳出家裡**。
2. 送到 Mac 的只有特徵（臉部特徵、聲紋特徵）與結果，不送原始影像或錄音。
3. 鏡頭開啟時一定有**看得見的提示**（眼睛螢幕的青色外環，§4.2）。
4. 隱私設定不能讓鴨子做出不安全的動作（例如為了不開鏡頭而盲走）。
5. 公開 repo 不放家人真實姓名與家中資料（根目錄 `CLAUDE.md`）。

### 2.2 可調整的設定

| 層級 | 開關 | 關掉的代價 |
|---|---|---|
| **全域** | 鏡頭 | 不能導航、找人、回充；鴨子只能原地對話或留在充電座 |
| | 常駐喚醒聆聽（麥克風） | 叫不醒鴨子；只能用 Nous 的其他終端或手把下指令 |
| | 臉部辨識 | 找人只靠聲音方向與聲紋，比較容易找錯或找不到 |
| | 聲紋辨認 | 不知道是誰叫的，只能找聲音來源 |
| | 主動找人（被叫醒後走過去） | 被叫醒後只原地回應 |
| | 帶看建圖錄影 | 不能建立或更新地圖 |
| | 夜間紅外線補光（[ADR-0002 §4.1](ADR-0002-indoor-localization-and-navigation.md#41-沒開燈時的備案紅外線補光2026-11-13-使用者同意以此為主)） | 沒開燈時鴨子看不到路，只能停下回報「太暗了」；暗處的叫起床、回充可能失敗 |
| **房間（每個地點）** | 可否進入（永遠／只限指定任務／禁止） | 禁止進入的房間無法在裡面完成任務；鴨子會停在門口回報 |
| | 房間內可否做臉部辨識 | 同上「臉部辨識」 |
| | 房間內可否出聲（說話、叫人） | 不能在該房間叫人或對話 |
| | 房間內可否開紅外線補光 | 該房間沒開燈時鴨子無法在裡面移動，會停在門口或原地回報 |
| | 時段（例如只限 07:00–08:00） | 時段外視同禁止進入 |
| **家人（每個人）** | 是否參與臉部辨識、聲紋辨認（沿用 AIOS 的主動登記） | 鴨子認不出這個人 |
| | 是否可以被主動找（例如「別來找我」） | 對這個人的找人任務會被拒絕 |
| **模式（一鍵切換的組合）** | 見 §2.3 | — |

### 2.3 模式（預設組合，可自訂）

| 模式 | 內容 |
|---|---|
| 一般 | 依上表的個別設定 |
| 訪客 | 不做任何身分辨識（臉、聲紋），不主動找人，不進入臥室 |
| 夜間（可排時段，例如 22:00–07:00） | 不主動走動、不出聲；喚醒聆聽可選擇保留；排程任務（例如叫起床）可設定為例外 |
| 完全隱私 | 鏡頭與麥克風都關；鴨子停在原地或充電座，只回應實體按鈕與手把 |

## 3. 誰可以改

- **收緊**（關掉某項、切到更嚴格的模式）：任何人隨時都可以，用語音（「鴨子，隱私模式」）、鴨子上的實體按鈕或設定頁都行。
- **放寬**（打開某項、切回較寬的模式）：**只能在 Mac 上的 Nous 設定頁操作**。不接受語音放寬，因為聲紋或人臉只是身分辨識，**不等於授權**（AIOS ADR-0001 的原則），也避免小孩或訪客用一句話打開鏡頭。
- 每次變更記錄時間、來源（設定頁／語音／按鈕）與變更項目，不記錄任何影像或聲音內容。
- 依 AIOS「功能便利性優先」的優先順序，設定頁本身不另外加密碼；若之後需要再加。

## 4. 在哪裡執行

規則要在**資料產生的地方**就擋下，而不是產生後才丟掉：

| 規則 | 執行位置 |
|---|---|
| 鏡頭、麥克風開關、房間是否可進入、可否出聲 | **鴨子（Pi 4 感知板）**：在開啟裝置或接受任務之前檢查 |
| 臉部比對、聲紋比對、家人是否可被找 | **Nous（Mac 核心）**：在比對或下達任務前檢查 |
| 模式與時段 | 兩邊都檢查（以同一份設定為準） |

- 設定存在 Nous 本機，以**版本化的設定文件**同步到鴨子（只含 ID，不含真實姓名）；schema 放在 `nous_duck/protocol/`（`privacy_policy.schema.json`，規劃中）。
- 鴨子拿不到最新版設定時（剛開機、斷線），使用**最後一次確認過的版本**；從來沒有拿到過，就用最嚴格的「完全隱私」。
- 違反規則的任務一律拒絕：工具結果 `refused`，原因代碼 `privacy_policy`（代碼清單待定），並說明是哪條規則，讓 Nous 能告訴使用者「哥哥房間現在不能進去」。
### 4.1 實體隱私開關（2026-11-12 決定加裝）

- 鴨子身上一個**實體撥動開關**，直接切斷 AR0144 鏡頭與 XVF3800 麥克風陣列的**電源**（兩者都由 USB 供電，切 USB 的 5V／VBUS）。關掉時鏡頭與麥克風在電氣上就不存在，任何軟體都打不開。
- 開關另有一組接點接到 Pi 4 的 GPIO，讓軟體**讀得到開關位置**：關閉時鴨子回報「實體隱私開關已關閉」，Nous 的狀態與 `app.duck.status` 照實顯示，不假裝還在聽或看。
- 關閉時的行為等同「完全隱私」：不能導航、找人、回充；在原地站好，只回應手把與實體按鈕。走路中被關掉，就停下站好。
- 打開開關**只恢復供電**，不會放寬軟體設定：鏡頭要不要開，仍依 §2～§5 的設定。
- 切斷電源時 USB 裝置會斷線，軟體要能處理斷線與重新連上（FamilyRecorder 已有 USB 斷線後自動恢復收音的作法可參考）。
- 位置：在機身上手摸得到、不容易誤觸的地方（例如背部上方），確切位置與開關型號在 `hardware/wiring/` 決定。

### 4.2 鏡頭狀態提示：眼睛螢幕（2026-11-17 修訂）

上游的眼燈是單色 LED，由 Pi Zero 的 GPIO D24／D23 開關（上游 runtime `eyes.py` 只做眨眼），**不能顯示顏色**。

- 2026-11-12 原決定：眼燈改成 RGB LED（每眼一顆可定址 RGB LED），由 Pi 4 驅動，用顏色提示鏡頭狀態。
- **2026-11-17 使用者改決定：兩隻眼睛改成 1.28 吋圓形螢幕**。眼睛除了提示鏡頭狀態，還能做眨眼、看方向與表情。下面是修訂後的內容。

#### 4.2.1 硬體

- 每眼一片 **1.28 吋 GC9A01 圓形 IPS TFT**，240×240，SPI 介面。
- 使用者 2026-11-17 已在蝦皮「777微電子」購買副廠模組（商品頁標示 1.28 吋、GC9A01、240×240）。**收貨後實測登記**：數量、腳位、外形與孔位、有沒有背光控制腳（BLK）、耗電、重量。副廠模組各家外形不同，兩片要同一批。
- **原版眼蓋放不下，眼框要重畫。** 從 STL 量的外框：`left_eye.stl`／`right_eye.stl` 與 `bulb.stl` 外徑 35 mm。微雪同規格模組的官方規格是外徑 37.5 mm、顯示區直徑 32.4 mm，副廠模組以實物為準。新眼框放 `hardware/expression_mods/`，不改上游檔。頭殼本來就要為 AR0144 重新設計（ADR-0005 §2.3），眼框跟頭殼一起畫。
- **由 Pi 4 驅動。** 2026-11-22 起鴨子是 Pi 4 單板（[ADR-0008](ADR-0008-single-board-pi4.md)），開鏡頭的也是它，提示才能直接跟著實際的鏡頭狀態走。
  - Pi 4 的 SPI0 有兩個片選（CE0、CE1）：兩片共用時脈與資料線，各接一個片選。SPI0 用 GPIO 7–11（實體腳 19、21、23、24、26），和 ADR-0008 §2.3 腳位表用到的腳不重疊。DC、RST、背光的 GPIO 與接線在 `hardware/wiring/` 決定。
  - 上游的眼燈腳位（GPIO 23／24，單板後在 Pi 4 上）不再接眼燈。上游 runtime 若仍會切換這兩支腳，先不要拿它們當螢幕的 DC 或 RST，確認 runtime 不再碰之後再說。投影燈（GPIO 25）不受影響。
  - Pi 4 裝在機身、螢幕在頭上，兩片螢幕的線（每片約 7 條）要穿過頸部 4 個關節（ADR-0008 §4.1），要留餘量並避開夾點。線拉長後 SPI 時脈可能要降，訊號與刷新率要實測。
- 驅動軟體、刷新率與 Pi 4 的 CPU 占用要做 spike 實測；ADR-0005 §2.1.1 已經擔心 Pi 4 的運算餘裕。
- 耗電與重量都待實測。耗電要算進 5 V 供電預算，重量要算進頭部重量（ADR-0005 §2.4）。

#### 4.2.2 提示規則

- 提示跟著**實際的裝置狀態**（鏡頭串流真的開著），不是跟著模式開關；這也是 AIOS「狀態以裝置事件為準」的規則。
- 用兩眼螢幕的**外環顏色**表示狀態，環內可以照常畫眼睛表情。顏色草案（可再調整；同時用亮度與閃爍方式區分，色弱也看得出來）：

| 狀態 | 眼睛螢幕外環 | 優先順序 |
|---|---|---|
| **鏡頭開著**（導航、找人、對話、回充） | **青色實心環常亮** | 最高：只要鏡頭開著就一定顯示，表情動畫、眨眼、轉場都不能蓋掉或淡出 |
| 鏡頭關、正在跟 Nous 對話（只用麥克風） | 綠色環慢呼吸 | |
| 鏡頭關、待機或充電（只聽喚醒詞） | 暖白低亮度，偶爾眨眼 | |
| 實體隱私開關關閉 | 紅色環短閃一次後轉暗紅低亮 | |
| 錯誤或需要幫忙（跌倒、迷路） | 黃色環閃爍；鏡頭開著時改為青色加黃色交替 | |

- **已決定（2026-11-17）**：眼睛螢幕**只畫合成圖形**，不顯示鏡頭畫面，也不顯示由原始影像產生的縮圖或人臉。這樣眼睛不會變成另一個看得到影像的出口。
- **已決定（2026-11-17）**：**螢幕不能顯示，就不開鏡頭。**
  - 顯示程式定期回報心跳。開鏡頭前先確認心跳正常；顯示程式停止或螢幕初始化失敗時，不開鏡頭，已開的要關掉，並回報眼睛螢幕無法使用。
  - 限制：GC9A01 模組通常只接寫入線，軟體無法確認畫面真的亮著（例如背光壞掉或排線鬆脫）。這種情況只能靠下面的硬體指示燈。
- 夜間與暗處：降低背光亮度，避免螢幕本身吵醒人，但「鏡頭開著」的青色環仍要看得出來。若模組沒有背光控制腳，只能把畫面調暗，背光仍會亮著，收貨後確認。紅外線補光燈的微弱暗紅光**不算**鏡頭提示，提示仍以眼睛螢幕為準。
- **已決定（2026-11-17）**：另加一顆**直接接在鏡頭電源上**的小 LED，鏡頭有電就亮，不經過任何軟體。眼睛螢幕的畫面完全由軟體控制，這顆燈才是軟體出錯也騙不了人的保證。
  - 接在實體隱私開關之後的鏡頭 5 V 上（§4.1），開關切斷時它也會熄滅。
  - LED 型號、顏色、亮度、限流電阻與安裝位置（要看得到、靠近鏡頭）在 `hardware/wiring/` 決定。夜間亮度要低，但不能有軟體關掉它的路徑。

## 5. 預設值（2026-11-12 使用者同意）

| 項目 | 預設 |
|---|---|
| 鏡頭 | 只在導航、找人、對話、回充時開啟；待機與充電時關閉 |
| 常駐喚醒聆聽 | 開 |
| 臉部辨識 | 公共區域開；**臥室預設關** |
| 聲紋辨認 | 開 |
| 主動找人 | 開 |
| 臥室進入 | 只限指定任務（例如「叫起床」） |
| 夜間模式 | 22:00–07:00，排程的叫起床任務列為例外 |
| 紅外線補光（建議，**待使用者確認**） | 鏡頭允許開的時候才可能開；公共區域開；**臥室只限指定任務**（例如叫起床），與臥室進入規則一致 |

以「叫哥哥起床」為例：任務是指定任務，可以進入 `brother_room`；臥室臉部辨識關閉，所以 `find_person` 改走到地圖上的 `brother_bedside`，用聲音叫人並聽回應。

### 5.1 記憶相關的開關（2026-11-26，ADR-0011）

使用者 2026-11-26 同意。細節與理由見 [ADR-0011 §8](ADR-0011-duck-memory.md#8-隱私)。

| 項目 | 預設 |
|---|---|
| 保存任務歷程 | 開，保留 30 天 |
| 歷程中記錄對象是誰（家人 ID） | 開；刪除家人資料時只拿掉 ID，紀錄保留 |
| 環境筆記（由任務歷程統計） | 開 |
| 鴨子終端取用家人記憶 | 跟 Nous 的記憶設定；訪客模式下不取用；夜間模式不念出記憶內容 |
| 在鴨子旁邊用語音寫入記憶 | 開；訪客模式下不能寫 |

## 6. 工具與介面

- `app.duck.status` 回報目前模式與主要開關狀態。
- 新增 `app.duck.privacy_tighten`（`reversible_write`）：只能**收緊**（切到更嚴格的模式或關掉某項）。**沒有給模型放寬的工具**。
- 設定頁屬於 AIOS 的介面，要依 AIOS 雙語規範提供繁體中文與英文；這是 AIOS repo 的批次。
