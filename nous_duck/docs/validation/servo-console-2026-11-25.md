- 分支：`claude/servo-console`（從 `claude/focused-dijkstra-ibeto1` 開出，接在 Pi 4 單板的工作後面）
- 對象：[`robot/servo_console/`](../../robot/servo_console/README.md)、頁面原始碼 [`assembly_viewer/web/src/console/`](../../assembly_viewer/web/src/console/)、[`deploy_console.sh`](../../robot/deploy/pi4/deploy_console.sh)

| 操作 | 結果 |

## 3. 實機部署與測試（Pi 4）

`bash nous_duck/robot/deploy/pi4/deploy_console.sh`：建置頁面、複製到 `~/duck/console/`、安裝 systemd 服務 `duck-console`（enabled、active）。測試時鴨子懸空，14 顆用上游 `turn_on.py` 擺著站姿出力中。用 HTTP API 從 Mac 操作：

| 步驟 | 結果 |
|---|---|
| 服務剛啟動 | 未連線、IMU 顯示「沒有連線」：**啟動時不碰硬體** |
| `connect` | 1.26 秒；14 顆都回應，14 顆出力中（沿用原本狀態，沒有改扭力）；溫度 29–33 °C、最低電壓 8.0 V；沒有警報 |
| 站姿回讀（扣掉偏移）對照上游 `init_pos` | 左膝 78.83°／78.4°、右膝 79.5°／79.0°、左髖前後 -35.91°／-36.1°、右髖前後 36.2°／36.4° |
| ID 32（head_yaw）目標 +5° | 約 1.2 秒後實際 5.14°（目標 5.05°）；送回原位後 -0.04° |
| ID 33（head_roll）放鬆 → 出力 | 兩次都成功，出力後角度不變（0.22°）：開扭力前先寫目前位置，沒有跳 |
| 目標 999° | 夾到 158.0°（`robot.xml` ±160° 內縮 2°），提示回傳給頁面 |
| 「停在這裡」 | 移動中按下，0.3 秒後停在 0.65°；再送回原位 0.05° |
| BNO055 | 讀得到：尤拉角、加速度、角速度；校準狀態 0/0/0/0（還沒校準）；溫度 -100 °C（和 [runtime 紀錄 §4.3](pi4-runtime-2026-11-22.md#43-bno0552026-11-23) 相同的異常值） |
| 足底開關 | 兩腳都「懸空」：感測器還沒接，腳位被上拉，符合預期 |
| 服務資源（連線中、頁面輪詢中） | CPU 約 9–10%、RSS 56 MB；`get_throttled=0x0`、CPU 44.8 °C |
| 重新部署（服務重啟） | 重啟後未連線；**14 顆仍出力**（重啟只釋放硬體，不改扭力） |

測試結束時控制台是「未連線」，鴨子維持站姿出力。

## 4. 沒有驗證的部分

- **沒有在實機上用網頁操作腿部**，也沒有測緊急停止讓整隻鴨子放鬆（使用者要求維持出力）；實機上的扭力關閉只測了 ID 33 一顆。緊急停止在單元測試與模擬匯流排測過。
- 沒有在實機上觸發溫度、電壓、讀取失敗、瀏覽器斷線的保護；門檻是暫定值。
- Claude 的內建瀏覽器打不開 `duck-pi4.local:8080`（導覽被拒絕），所以**實機頁面沒有用瀏覽器看過**；API 與頁面用的是同一組端點，頁面本身在模擬匯流排下測過。
- 控制迴圈實際頻率沒有量（設計 50 Hz；14 顆位置讀取約 1.9 ms，見 [runtime 紀錄 §4.4](pi4-runtime-2026-11-22.md#44-舵機匯流排唯讀掃描2026-11-25)）。
- 偏移存檔、姿勢存檔在實機上沒有操作（單元測試有）。
- 手機實際連 Pi 操作沒有測。
