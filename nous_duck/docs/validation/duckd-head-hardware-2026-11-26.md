### 第二輪（18:44:13–18:45:58）— 作廢，留作參考

### 診斷（18:46–18:48，頭做一次 14° 來回，同時記角度、能量、頭部 yaw）

1. **自激確實存在**：頭轉動的約 1.5 s 內，語音能量升到 1e5–3e5，方位指向舵機聲；頭不動時能量是 0。

3. `DOA_VALUE` 的角度和 `AEC_AZIMUTH_VALUES` 自動選擇波束的方位數值相同（88／89、156／155、142／142），同一個零點、同一個方向。

- 改用語音能量判斷有沒有語音（`speech_source: energy`，能量大於 `min_speech_energy` 才算），方位用自動選擇波束的方位。

- 追蹤的上限改用接手後的實際視窗（原本事件回報 `head_yaw_rad: 0.5`，實際只到 0.26）。

## 9. 給 B 線：duckd 重啟後 hub 丟掉新事件

- **現象**：18:50:58 我重啟 duckd（重新部署），18:51:10 重連之後，`duckctl events` 看不到任何新的 `tracking_acquired`／`tracking_lost`；但 duckd 確實有在轉頭（回讀）。
- **證據**：`duckctl link` 的計數 `duplicateEvents` 從 0 變成 11（18:56），測試結束時是 23（19:01）；重啟前的事件都正常顯示。
- **推測原因（沒有讀 hub 的程式確認）**：duckd 的事件編號在行程重啟後從頭算，hub 用事件編號去重，把新事件當成重複丟掉。
- **影響**：Nous 端在鴨子重啟後會收不到事件，直到編號超過重啟前的最大值。
- 這一批沒有修（不在 A 線這次的範圍；要決定是 duckd 讓編號跨重啟唯一，還是 hub 在新連線時重設去重表）。

```bash
bash nous_duck/robot/deploy/pi4/deploy_duckd.sh
```

```bash
bash nous_duck/robot/deploy/pi4/setup_doa.sh
```

```bash
bash nous_duck/robot/duckd/tools/head_check.sh
```

聽聲轉頭：Pi 上 `sudo systemctl start duckd`、`~/duck/duckd/duckd-ctl engage`、`sudo systemctl start duck-doa`；Mac 上 `nous_adapter/scripts/duck-link-dev.sh hub-start`、`tunnel-start`，再 `bin/duckctl track sound`。停止：`ssh duck-pi4 'sudo systemctl stop duckd duck-doa'`。
