# 加裝後的質量模型：單板 Pi 4＋加裝件對上游步態的影響（模擬）

- 日期：2026-11-26
- **驗證層級：模擬（MuJoCo）＋單元測試**。加裝件的重量與位置**全部是估計**，沒有一件秤過；Pi 4 在機身裡的位置也還沒決定。**不是實機結果。**
- 分支：從 PR #32 的 `claude/duck-companion-overnight`（`057d52e`）開出，用它的 `walk_sim`。
- 相關：[ADR-0005 §2.4](../adr/ADR-0005-compute-and-sensor-upgrade.md#24-重量與步態策略)（加裝後要重測步態）、[ADR-0008 §4.3](../adr/ADR-0008-single-board-pi4.md#43-散熱記憶體重量)（Pi 4 從頭移到機身）、[走路模擬紀錄](sim-nav-2026-11-25.md)（PR #32 的基準數字）
- 原始數字：[`data/mass-model-2026-11-26.json`](data/mass-model-2026-11-26.json)

## 1. 結論

1. **依目前的估計重量，上游步態策略不需要重新訓練**（模擬層級）。整隻從 2.06 kg 變成 2.27 kg（+209 g；上限情境 2.45 kg，+387 g），以下各項和上游模型幾乎一樣：
   - 走路 45 次、隨機指令 40 個種子 × 60 秒：**都沒有跌倒**。
   - 起步門檻不變：前進要 ≥ 0.10 m/s，後退要 ≤ −0.12 m/s。
   - 前進速度比 0.767 → 0.760（上限情境 0.739）；後退 0.346 → 0.320（上限 0.297）。
   - 動作庫初版範圍（ADR-0011 §2.3）內的頭部動作，站著時全部穩定。
2. **頭部比機身敏感，但還有餘裕**：在估計值之外，頭前方再加 **150 g**，站著時 neck_pitch −0.34 才開始跌倒；同樣再加 100 g 還沒出問題。機身頂面再加 **800 g** 還能走，只是速度比降到 0.63。
3. **舵機比模型弱，影響比加裝件大得多**。把舵機 kp 降 20% 當作「實際比模型弱」的代理（電壓、背隙、摩擦都會造成，**沒有校正過**）：前進速度比從 0.77 掉到 0.48，**後退完全起不了步**（0/9）。上游模型本身就會這樣，跟加裝件無關。
4. **Pi 4 放哪裡，影響很小**：前、中、後、下四個位置的結果差不多。唯一的差別是放後面（top_back）時，−0.10 m/s 也能後退起步（其他位置要 −0.12）。
5. **頸部力矩**：在上游訓練的頸頭角度範圍內，neck_pitch 的最大靜態重力力矩是 0.50 → 0.54 N·m（上限情境 0.63 N·m）。STS3215 規格約 19 kg·cm ≈ 1.86 N·m，分別是 27%、29%、34%（只算靜態重力，不含加速度）。

所以這次模擬改變的是**量測的優先順序**：先秤重、確認 Pi 4 位置，並把「實機的速度比與起步門檻」列為 P1 上機後最先要量的數字，因為舵機實際有多強，比加裝件重多少更關鍵。

## 2. 做法

### 2.1 質量模型

[`sim/walk_sim/mass.py`](../../sim/walk_sim/mass.py) 把每個元件合進上游模型對應 body 的慣量，不改上游 `robot.xml`：

1. 元件的位置寫成**起始姿勢時的 base 座標**。程式在起始姿勢做一次正向運動學，換算成 body 自己的座標。頭的座標跟 base 差了 90°，單元測試有檢查這段換算。
2. body 原本的慣量和元件的慣量（長方體外形）都換算成「對 body 原點」的張量（平行軸定理），相加或相減後求新的質心，再換回對質心的張量並做特徵分解，寫回 `mass`、`ipos`、`iquat`、`inertia`。
3. 拿掉元件（頭裡的 Pi Zero 2 W）用相減。結果不合理（質量 ≤ 0、不是正定、不滿足三角不等式）時直接報錯。

PR #32 原本的 `extra_mass_kg` 是加在 `base` 上的點質量，只能加、位置只能放在機身。這次的做法可以放在任何 body 上、可加可減，所以頭部的變化也算得到。

### 2.3 情境與量測

[`sim/walk_sim/mass_compare.py`](../../sim/walk_sim/mass_compare.py)。每個情境跑同一套量測，起步相位取 0、3、…、24（9 個）：

| 量測 | 做法 |
|---|---|
| 站立 | 速度 0，20 秒 |
| 走路 | vx ±0.15、yaw ±1.0、vy 0.2，每個指令 9 個起步相位、各 8 秒；前 3 秒當起步 |
| 起步門檻 | vx 0.06～0.12、−0.10～−0.15，各 9 個相位、6 秒，看最後 2 秒有沒有在踏步 |
| 頭部 | 站著以 1 rad/s 轉到目標、維持 5 秒：動作庫初版範圍，加上 PR #32 量到會跌倒的角度 |
| 跌倒率 | 同 PR #32 `measure.fall_rate`：40 個種子 × 60 秒、隨機指令（上游範圍）、加速度限制、訓練等級的感測雜訊 |
| 頸部力矩 | 機身固定，neck_pitch −0.34～1.1、head_pitch −0.78～0.78 的 9×9 格點，取靜態重力力矩的最大值 |
| 加重餘裕 | 在估計值之外，頭前方再加 0～200 g、機身頂面再加 0～800 g，重跑走路、起步門檻、頭部、站立 |

PR #32 的跌倒率在機身加 0.2／0.4 kg 時都是 0 次，分不出差別，所以這次另外加了起步門檻、頭部大角度和加重餘裕這些比較敏感的項目。

環境：雲端容器（Linux x86_64、4 核）、Python 3.12.3、mujoco 4.0.1、numpy 2.5.4、onnxruntime 1.32.0（`sim/requirements.txt` 鎖定的版本），策略 `BEST_WALK_ONNX_2.onnx`。完整跑一次約 18 分鐘。

## 4. 限制

- **重量與位置都是估計**。最大的不確定是 XVF3800 Flex、喇叭、散熱與新頭殼，下限到上限差了 240 g。
- 元件用長方體近似，只影響元件自己的轉動慣量；對整體的影響主要來自質量與位置。
- kp −20% 只是「舵機比模型弱」的代理，沒有對照實機校正；真正的舵機特性（電池電壓下降、背隙、溫度）要在實機上量。
- 沿用 PR #32 模型的差異：沒有背隙關節、地面平坦、摩擦固定 0.6（見 [sim-nav §9](sim-nav-2026-11-25.md#9-模擬與實機的差距)）。
- 頸部力矩只算靜態重力，沒有算頭轉動時的加速度，也沒有算舵機的溫升。
- 線材穿過頸部的拉扯、外殼和線材的摩擦都沒有模擬。

## 5. 下一步

1. **秤重**：Pi 4（含散熱）、UBEC、XVF3800 Flex、喇叭、AR0144、GC9A01、觸點板。秤完改 `mass_budget/p2_single_pi4.json`（`source.kind` 改成 `measured`），重跑一次，寫新的驗證紀錄。
2. **決定 Pi 4 位置**（ADR-0008 §5.1）。模擬裡位置的影響很小，可以優先考慮散熱與走線。
3. **P1 上機後最先量**：實機的速度比與起步門檻。kp −20% 的結果顯示，舵機實際有多強，比加裝件重多少更關鍵。實機和模擬差很多時，先校正模型的舵機參數，再判斷要不要重新訓練。
4. 頭部 head_yaw −1.0 單邊會跌倒的原因，可以另外查（模型不對稱，或策略本身的行為）。
